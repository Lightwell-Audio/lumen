| 2026-10-10 (M5 slice 1; observed 2026-10-11) | **MIDI To timing is unmeasured on real hardware.** The sender maps device frames to time with the audio callback's clock and the driver-reported output latency (ADR-0045); it is tested only against the fake backend (worst lateness about 1.5 ms). | 2026-10-11 (M5 slice 2) | **Live MIDI timing is unmeasured with a real controller.** The feed maps driver stamps to frames (ADR-0046) and is tested with injected times; WinMM's stamps have millisecond resolution, and each driver's delivery adds its own delay. | A live part may feel slightly late or uneven at large buffers | MT-MIDI-3 step 3 (the owner plays); recording (slice 6) uses the same times |
| 2026-10-11 (M5 slice 2) | **A live note and a clip note on the same key share the synth's key**: the engine sends each its own note-on and note-off, but the synth may end both voices on the first note-off. | A held live note can stop when a clip note on the same key ends | When the device chain arrives and instruments track notes by source (M6/M8), if heard |

| 2026-10-10 (M5 slice 1) | **Translating a changed MIDI clip copies its notes** (`midi_play::engine_midi` rebuilds the lists of every clip that changed), and the engine compares clips by pointer, then by content. | 2026-10-10 (M5 slice 1) | **Limits per MIDI track:** 128 notes held at once and 1,024 events queued per block; past that new ones are dropped and counted (`MidiPlayer::dropped`), with nothing shown to the user. | 2026-10-10 (M5 slice 0) | **No virtual MIDI ports, and WinMM opens an input for one program at a time.** midir cannot create ports on Windows, and a device held by another program (a DAW, a browser using Web MIDI) will not open; the row says "Could not open". | Another program can lock a controller out of Lumen; Lumen cannot offer a port to others | A loopback driver (loopMIDI) is the Windows answer, noted in MT-MIDI-1. | 2026-10-10 (macOS CI) | **Space and Shift+Space toggle by what the audio thread last reported.** `Transport::play_stop` and `pause_continue` read the engine's transport state, which changes at the next audio block, so a second press before that block repeats the first command (Stop, Stop) instead of toggling back. Found as an E2E flake on a loaded macOS runner; the tests now wait for each change to be heard. | Two presses within one buffer (about 5 ms at 256 frames, 46 ms at 2048) leave playback stopped or playing; rare by hand | Toggle from the last command sent until the engine confirms it, with an E2E test; to pitch to the owner (it changes how Space acts) |
