## Findings

### High

- **H1 A project swap leaves the recorder, learn and gesture state behind, and
  a pass under way is written into the new project** (`app/projects.rs`
  `replace_document`, `app/auto_recording.rs`, `app/controllers.rs`; *verified*).
  `replace_document` resets `lanes`, `arrangement` and the chain, but not
  `self.recorder` (the passes in progress), `self.gestures_open`, or
  `self.controllers` (`learning`, `held`, `last`). Reproduced: a track in Write
  mode, a lane shown, the song playing and a pass under way; another project
  opened (its track has the same id, as every project's first track does).
  The next frame the recorder sees the mode gone, finishes the pass, and
  `write_pass` writes it into the *opened* project's track with that id: the
  project gains a lane it never had, is marked unsaved and has an undo step
  "Record automation" (`lanes in the opened project: 1`, `dirty: true`,
  `undo: "Record automation"`). The same state crossing holds for a control
  waiting to learn: the next controller moved maps the same-id control of the
  other project. Consequence: a lane or mapping the user never made in a
  project they only opened, which a save then keeps. This breaks "never lose or
  corrupt user work". *Also seen, not an M7 finding:* playback continues after
  the swap (the transport only locates to zero).

### Medium

- **M1 A lane pass lives only in the recorder until Stop or release**
  (`app/auto_recording.rs`, `auto_record.rs`; *read*). Write and Latch passes,
  and a long Touch, put nothing in the project until the pass ends, so autosave
  holds none of it; MIDI takes commit about once a second and autosave runs
  every 10 s while recording (M5). A crash, a power cut or closing the window
  during a long pass loses the whole pass. The quality bar allows a couple of
  minutes. Fix options: commit the pass-so-far into the lane at an interval
  (as one undo step that later extends, as the MIDI take does), or flush at
  quit and at device loss at least. The owner chooses.
- **M2 Three files grew past the point where one concern fits**
  (*scan*). `app/testing.rs` 1,527 → 1,916 lines (every slice added its seams
  to one file; 389 lines in M7), `app/commands.rs` 869 → 1,019 (a table and its
  dispatch), `lumen-project/src/model.rs` 905 → 970. `routing.rs` is 1,023
  lines but 314 of them are production code. Split `testing.rs` by area
  (`testing/automation.rs`, `testing/mixer.rs`, and so on) before M8 adds more
  seams; split the command dispatch by area.
- **M3 The quality bar's frame-time claim for 200 tracks with visible lanes is
  unmeasured in release** (`KNOWN_ISSUES`, A1; the A7 notes say it is still
  due). The debug build showed no jump; GPU frame times need a real window.
  Owner step in MT-AUTO-10: `--stress --bench-lanes --bench-frames` on the
  Windows machine, at 100% and 200%, and record the numbers.
