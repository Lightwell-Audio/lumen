## Findings

### High: breaks a stated rule

None.

### Medium: architecture and maintainability

- **M1 Modules past the size limit.**
  - `arrangement/mod.rs` has 1,152 lines (928 without tests). It was 611 at the end of M3. It mixes row layout and zones with track selection and track commands.
  - `arrangement/strip.rs` (882) has a 270-line `strip()`.
  - `arrangement/headers.rs` (862) has a 500-line `headers()`.
  - `lib.rs` (856) has a 280-line `ui()`.
  - `arrangement/clips.rs` (810) is just past the limit.

  Rule: modules stay small and single-purpose, and are split past about 800 lines. Consequence: M5's piano roll and the clip editor tab land in these files, so they must be split now.
- **M2 `widgets::value_slider_lifted` carries `#[allow(clippy::too_many_arguments)]`.** It was added with the header meters (8 parameters). Rule: no long parameter lists; use a parameter struct. Consequence: the next variant adds a ninth.
- **M3 A plan swap copies every delay line on the audio thread.** `Plan::carry` → `Lines::carry` copies each line's ring sample by sample, with a `%` per sample, whenever a new plan arrives. That includes plans that only change a level (each step of a fader drag). The cost grows with the total compensation length: 64 tracks compensated by 100 ms copy about 600,000 samples in one block. That is likely a large part of the 2.7 ms budget at 128 frames. The perf gate's latent scenario never swaps plans, so the cost is unmeasured. Rule: no dropouts while editing (quality bar). Today only the synthetic test device adds latency, so nobody can hit this until VST3 hosting (M6). Fix: when a line keeps its key and length, take over the old ring whole (swap the buffers), and copy only lines that changed length. Add plan swaps to `engine_latent_64`.
- **M4 The accessibility test covers M3 views only** (`every_control_in_every_m3_view_has_a_name`). The Mixer tab, unfolded sends and returns, the output and pan-law menus and the compensation readout are not checked. The review's probe found no unnamed control today. Without the test, a regression would go unseen. Fix: extend the test to M4's views.

### Low: consistency and polish

- **L1 Font sizes outside the tokens.** `strips.rs:288` uses `FontId::monospace(20.0)`. `strips.rs:339`, `strips.rs:389` and `widgets/meter.rs:95` use `theme::size::CAPTION - 1.0`. Fix: add a `size::METER` token (10 pt) and a token for the loudness figure, in both palettes and DESIGN.md §3.
- **L2 A repaint interval literal.** `headers.rs:755` uses `Duration::from_millis(33)` for the meters' repaint. Fix: move it to `motion`, next to the other rates.
- **L3 "Inside Lumen"** (`strip.rs:608`, the output menu's heading) names the product in a literal. Fix: use `PRODUCT_NAME`.
- **L4 Docs drift.** `ARCHITECTURE.md` does not mention `app/clipboard_keys.rs` (added after slice 7) or `lumen-engine`'s `snapshot.rs`.
- **L5 A stray empty file `C`** in the repository root (untracked).
- **L6 Records.**
  - `MANUAL_TESTS.md` does not yet record the owner's passes of MT-APP-17, MT-MIX-1, 2, 5 (run 2), 6, 7 and 8.
  - The dropout-count entry in `KNOWN_ISSUES.md` is closed by MT-MIX-1.
  - The M4 plan's slice table still says "waits for the owner".
- **L7 The WSL scripts default to `main`.** `clippy.sh` and `perf.sh` reset to `origin/${LUMEN_REF:-main}`, and `DEVELOPMENT.md` does not say so. Run before pushing a branch, they check the wrong code and pass. Fix: document `env LUMEN_REF=<branch>` in DEVELOPMENT.md.
- **L8 `media.rs:123` reads a file's size (`fs::metadata`) on the UI thread** when an import starts. This dates from M2. It is a stat, but on a network path it can stall a frame. Fix: take the size in the loader thread.

## Recommended order

1. Records and housekeeping (L5, L6, L4, L7): no code risk, so the merge carries true records.
2. M3, the delay-line swap, with its perf scenario. It touches the engine, so it gets the gate in WSL.
3. M1 and M2, the splits: pure moves, one commit per file, gates after each.
4. M4, extending the access test.
5. L1, L2, L3, L8: small, one commit.

Then the M4 report in `PROGRESS.md`, `CLAUDE.md` §12, and the merge into
`main`.
