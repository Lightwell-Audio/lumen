# M7b E6 and application UX audit — 2026-10-24

Branch: `m7b-s6-close`. The owner requested the editing closeout review plus
an application-wide inspection of menus, interactions and visual consistency,
with small fixes applied and larger work listed for planning. That instruction
authorizes the fixes below. No new milestone is started by this audit.

## Scope and evidence

The architecture, design, documentation, branching and review skills, saved
design tokens, M7b plan and known issues were used. Three bounded GPT Luna
reviews covered core/audio/persistence, application chrome/devices/mixer, and
arrangement/editors/automation. The coordinator checked their findings and
integrated the corrections. This was a broad sweep, not a line-by-line proof
of every crate or every possible interaction.

The earlier capture pass produced **326 PNGs** in `target/audit-shots`, across
transport, application menu, palette, shortcuts, audio/MIDI settings, browser,
track/clip/range/ruler menus and submenus, mixer, device chain, MIDI editor,
quantize, controller lanes, automation, history and project prompts. These
cover dark 100%, light 150%, and dark 200%; the 200% cases use the 960 × 540
minimum logical window. Reviewers inspected representative images, not every
PNG. Capture helpers use partial accessible-name matching; a missing target
is a harness coverage gap, not evidence that the product lacks the control.

The corrected-menu pass adds **30 PNGs**, covering both themes at 100/150/200%.
Screenshots are GPU-rendered app-harness states with isolated test settings
and fake audio. Dropout counts in these slow captures do not measure normal
audio performance. Native plugin editors, physical devices, recovery after
an actual crash, screen-reader output, and detached native windows need the
owner's manual runs. No current physical-hardware performance claim is made.

## Findings and status

| ID | Severity | Finding and consequence | Status |
|---|---|---|---|
| H1 | High | `app/clip_consolidate.rs`, `app/clip_bounce.rs`, `app/track_freeze.rs` created directories on the UI thread. Slow storage could stall input before the background render began. | Fixed: directory creation and errors moved to the render workers; nested output-folder and failure coverage retained. |
| H2 | High | `arrangement/menus.rs` exposed 12 clickable track-colour swatches without names or focus feedback. Assistive navigation could not identify them. | Fixed: numbered accessible names, tooltips and the shared focus ring; recolour/undo regression scenario. |
| L1 | Low | Long grid menus exceeded the window, leaving small subdivisions and feel options below its bottom. The audio status popover also clipped lower rows. | Fixed: shared menu scroll area bounded by window height; project menu uses the same wrapper. Small-window grid scrolling has a regression scenario. |
| L2 | Low | Automatic crossfades used a lit menu row while nearby preference toggles used switches. | Fixed: shared switch, preserving the existing project command and undo behavior. |
| M1 | Medium | `app/preferences.rs` changed Copy imported audio without scheduling a settings write. Restart could discard the preference unless another setting caused a save. | Fixed: `.changed()` schedules the existing background writer; isolated restart scenario. |
| H3 | High | `widgets/keys.rs` gave keyboard-focused menu rows the hover fill without the required accent focus ring. | Fixed for menu and submenu rows with the shared focus-ring painter. |
| M2 | Medium | `lumen-project/src/edit/consolidate.rs::is_current` checks selected clips only. A new unselected clip moved into the output span during rendering can be cut by `overwrite` when the old result commits. Undo recovers it, but a newer edit is silently replaced. | Fixed in M9 R0 (ADR-0099): the part records every clip touching its span and is applied only if that set is unchanged. |
| M3 | Medium | `app/clip_normalize.rs` carries clip IDs and peaks, then commits gains without checking that each source/window still matches the scan. Editing during the scan can normalize against old audio. | Fixed in M9 R0 (ADR-0099): the scan carries the file, direction and stretch it read, and a changed clip keeps its gain and the note says so. |
| M4 | Medium | Several existing actions have no registered command: loop/metronome toggles, opening audio/MIDI settings and history, browser visibility, and adding return/group tracks. The command registry cannot cover these controls. | Open: command-coverage slice in preferences/keyboard hardening. Audit each action and its context, rather than adding duplicate commands mechanically. |
| M5 | Medium | Long source modules and literal geometry remain in older UI code. The mechanical scan is not evidence that each literal is a defect; several long modules include mostly tests. | Existing architecture debt: split by responsibility before extending each module; retain the earlier known-issue record. |

## Larger UX work for planning

M2 and M3 are confirmed by tracing the planner, worker result and commit
code; this audit did not add a deterministic race reproducer. Their follow-up
must first reproduce the concurrent edit and prove that the fix rejects it.

| Work | Proposed home | Reason |
|---|---|---|
| Reject stale normalize/consolidate results | M7b follow-up before M9 recording | Protect edits made while background work runs; requires race-oriented tests and explicit commit rules. |
| Complete command coverage and keyboard menu review | Preferences / accessibility hardening | Existing functionality should be searchable and usable without a pointer. Include individual clip/note accessibility and a real screen-reader run. |
| Complete Samples/Projects browser and audition | M9 | Devices is currently the only browser tab; already tracked, not a regression. |
| Complete project lifecycle, preferences and audio export | M9 | Save copy/template/revert, full preferences and export remain planned capabilities; disabled or absent flows should not be presented as finished. |
| Tap tempo and remaining transport options | Transport follow-up within M9 or hardening | Tap tempo is explicitly incomplete in PROGRESS; choose the behavior before implementation. |
| Reverse/polarity badges and persistent task feedback | Editing polish, with owner specimens first | Already-known discoverability limitations; new visual treatment needs the owner's selection. |
| Real plugin freeze/unfreeze and device/DPI checks | Existing MT-EDIT-6 and hardware/plugin manual tests | Headless screenshots cannot validate native editor focus, device recovery, or sound on the owner's hardware. |

Possible text cutoffs in old captures, Master Solo/Cue wording and the audio
budget legend were inspected as candidates. They are not confirmed defects:
the master button is a cue action by design, the legend text is intentional,
and the budget popover's lower-row clipping is covered by L1. No wording or
feature hierarchy was changed on those guesses.

## Validation and limitations

### Owner corrections after the first audit pass

The owner reported four visual problems on 2026-10-24. The compact tempo
field now stays inside its well padding, with its own button padding removed
and painting clipped to its value area. Single-letter shortcut caps use one
common width instead of each glyph's width. The shortcut search uses the
shared spacing tokens for its inset and control height. Automatic crossfades
moved from the application menu to the arrangement context menu; Undo/Redo
keep short application-menu labels and History records Enable/Disable
automatic crossfades. The saved command ID and category are retained for
shortcut compatibility. These supersede the initial location described in L2.

Regression coverage: `crossfades::the_automatic_setting_the_command_and_the_menu_roundtrip`
and `widgets::keys::tests::single_letter_keycaps_have_equal_widths`; existing
transport-fit and shortcut-editing scenarios cover the surrounding flows.
`audit_shots::scenes::owner_polish` captures all four corrections in both
themes at 100/150/200% under `target/audit-owner-polish`.
