# M9 slice R3 — Takes and Capture MIDI: plan

**Status:** Planned 2026-10-25, branch `m9-s3-takes-capture` (cut from `main`
after PR #63). Owner choices taken the same day: audio takes A, MIDI takes A,
Capture MIDI A (§3). Two smaller calls are open (§4). Nothing is built yet.

**Goal (M9.md §5, CLAUDE.md §6.2, §6.3).** Record with Loop on and keep every
pass: the last pass plays, the earlier ones are one click away in a Takes menu
on the clip. And never lose a phrase played while not recording: one command
turns the last notes played on a MIDI track into a clip.

**Not in R3:** take lanes and comping (later), a new overlap rule, the
loopback helper (R2b), anything for audio that records without a loop.

## 1. What the code gives us

| Area | Fact | Consequence |
|---|---|---|
| Audio loop recording | R2 writes one continuous file across loop wraps and places one long clip (`take_worker.rs` header; `audio_take::apply`). The worker already tells a wrap from a gap (a jump in `at` with `device` continuous). | The worker records the file frame of each wrap; placement cuts the file into passes. No new capture path. |
| Clip model | `Clip` has `loop_phase`, `audio_phase_seconds` (signed, can reveal earlier source frames) and `ClipContent::{Audio{offset}, Midi{notes,events}}`. Format is v30. | One optional `takes` field on `Clip` (v31). A pass of audio is a source anchor; a pass of MIDI is its notes and events. |
| MIDI loop recording | `recorder::Capture` numbers notes by loop pass (`Captured::pass`); `edit::record::place` layers every pass into one clip in Replace and Overdub (ADR-0055). | Replace keeps the pass number on each note and splits by it; Overdub stays as it is. |
| MIDI capture | The engine pushes `Captured` only for tracks with `record.is_on()` while `cx.recording` (`midi/player.rs`). `Captured.at` is a heard timeline sample, which is the same for every note while the transport is stopped. | Capture MIDI needs the engine to push messages when not recording too, with the device frame and whether the transport was moving. |
| Placement of a take | `record::place(.., Mode::Overdub)` carries what the clips under a take played there, so nothing heard is lost. | A captured phrase uses Overdub placement: it never destroys what is on the track. |
| Recovery | The sidecar (`<take>.take`) holds the track, start and rate; recovery repairs the header and puts the take back as one clip. | The sidecar also lists the wraps so a recovered loop take is cut into passes too. |

## 2. Design

**The model (format v31).** `Clip.takes: Option<Takes>`, written only when set:

```
Takes { active: u32, count: u32, others: Vec<(u32, Pass)> }
Pass::Audio { offset: i64, audio_phase_seconds: f64 }   // where the clip starts in the file
Pass::Midi  { notes: Vec<Note>, events: Vec<ClipEvent> }
```

Passes are numbered from 0 and shown from 1. The clip's own content is the
active pass, so editing it (a note, a gain, a trim) never leaves a stale copy;
`others` holds the rest. Playing pass `k` is a swap: the clip's current pass
goes into slot `active` and slot `k` becomes the clip's content. The engine
sees an ordinary clip, so nothing in playback changes. One undo step per swap.

**Audio passes.** The worker notes the file frame of each loop wrap (in
`TrackResult.wraps` and in the sidecar at every header refresh). With two or
more passes, placement makes one clip over the loop window (the loop's start to
where recording stopped, or the loop's end) that plays the last pass, and fills
`others` with the source anchor of each earlier pass. The model never lets a clip begin before its file
(`validate`), so a first pass that began part-way into the loop is not offered
as a take (its audio stays in the file); one that began at the loop's start
is. The file is never split: every pass is a window on the same media. A recording with
no wrap places the clip exactly as in R2 and has no `takes`.

**MIDI passes (Replace).** The recorder keeps each note's pass; `place` makes
one clip over the loop window with the last pass as its notes and the earlier
passes in `others`. Held notes follow the existing wrap rule per pass.
**Overdub** keeps today's layering into one clip (that is what overdub means).

**The Takes menu.** On a clip with takes, the clip context menu has **Takes ▸**:
one row per pass ("Take 3 of 5", a check on the playing one) and, below, **Play
next take** / **Play previous take**, **Extract this take to a new track** (audio only: a
copy of the clip playing the chosen pass on a new track after the source, one
step; a new MIDI track would have no instrument) and **Keep only this take** (drops the others; the file stays in the
media pool). The clip shows a small **2/5** chip in its label while it has
takes. Commands `clip.take_next`, `clip.take_previous`, `clip.take_extract` and
`clip.take_keep` go at the end of `Command`, in the palette and the menus, with
the keycaps from the keymap. Menus list only what can apply: a clip without
takes shows none of them.

**What edits do to takes.** Move, copy, duplicate, trim, rename, recolour,
mute, lock, fades, gain, envelopes and note editing keep the takes (copies
copy them). Edits that rewrite what a clip plays (split, join, crop,
consolidate, bounce, reverse, unloop, normalize) **settle** the clip first:
the clip keeps the pass it plays and drops the others, in the same undo step,
and the notice says so ("Kept take 3; 4 other takes were removed. Undo brings
them back.") See §4 for the alternative.

**Capture MIDI.** The engine pushes the messages of every MIDI track that is
listening (armed, or the computer keyboard's target) when not recording too,
now carrying `frame` (the device frame) and `moving` (the transport was
running). The app keeps a rolling buffer per track (the last 10 minutes and at
most 20,000 messages; memory only, never saved, cleared when the project
closes), paired into notes by the same `recorder::Capture` rules.

A buffer is cut into **phrases** at every transport start, stop and locate. The
command **Capture MIDI** (Shift+F9, palette, and the Record button's menu)
turns the newest phrase with notes into a clip on the selected MIDI track (or
the armed one, or the one played last):

- played while the transport moved: the notes land at the timeline position
  they were heard at, like a recording;
- played while stopped: the first note lands on the playhead, the rest keep
  their time from the device frame at the project's tempo, and the clip starts
  on the bar line at or before the playhead.

It uses Overdub placement (nothing under it is lost), is one undo step, and
says "Captured 48 notes on Keys at bar 17." with Undo in the toast. A switch
**Keep played notes for Capture MIDI** (on by default, in the Record settings
beside the count-in) turns the buffer off and empties it.

| Choice | Taken |
|---|---|
| Audio loop takes | **A:** the last pass plays; a Takes menu swaps passes, extracts one to a new track |

## 4. Open (defaults taken unless the owner objects)

1. **Edits that rewrite a clip.** Default: they settle the clip and drop the
   other takes, said in a notice, undoable. The alternative is to keep the
   takes through a split (audio is cheap, MIDI would split every pass's notes)
   and refuse the rest; more work, and a split clip with takes on both halves
   is harder to read.
2. **Audio and MIDI recorded together are still two undo steps** (KNOWN_ISSUES,
   2026-10-25). Default: leave it; R3 does not touch the commit path. Making
   it one step means holding the MIDI commits until stop.

## 5. Parts (commits on the branch)

1. **Model:** `Takes`, `Pass`, format v31 with migration and golden, the pure
   edits in `lumen-project` (`edit::takes`: swap, next/previous, extract, keep
   only, settle). Tests: swap is its own inverse, notes edited on
   the active pass survive a swap, a pass of the wrong kind is refused.
2. **Audio passes:** wraps in the worker, the sidecar and `TrackResult`;
   placement cuts passes; recovery cuts them. Tests on a ramp: each pass's
   first sample.
3. **MIDI passes:** pass on `TakeNote`, `place` partitions in Replace;
   Overdub unchanged. Tests: Replace and Overdub with three passes, a note
   held across a wrap.
4. **Takes UI:** the menu, the chip, the four commands, settle on rewriting
   edits with the notice; `Document` methods, one undo step each.
5. **Capture MIDI:** the engine pushes when not recording (`frame`, `moving`),
   under the allocation guard; the buffer, phrases, placement, the command,
   the toast and the setting.
6. **E2E, MT-REC-3, docs:** scenarios on the fake backend (loop-record three
   passes, swap, extract, undo, save and reopen, kill and recover; capture
   while playing and while stopped, undo); ADR-0104; PROGRESS, ARCHITECTURE,
   MANUAL tests, `CLAUDE.md` §12.

## 6. Gates and honesty

The usual gates (fmt, clippy `-D warnings`, workspace tests, E2E, smoke, macOS
cross-clippy, WSL clippy and perf, since the model and the MIDI path change).
The format gate is v31's migration and frozen golden. The performance gate may
move: one more `Clip` field (the same `compact_scalar_arrays` note as v29).
Verified here: the model, the pass cutting on the ramp input, the MIDI
partition, the buffer and placement. **Not verifiable here:** that the passes
line up by ear with a real interface and its latency, and Capture MIDI from a
real keyboard; those are MT-REC-3 on the owner's machine.

## 7. Risks

1. **A pass boundary a block off.** The wrap frame comes from the capture
   chunks; the ramp E2E checks every pass to the sample.
2. **Latency shift past the loop start.** The placed loop start less the
   shift can fall before sample 0; placement skips the frames before 0 for
   every pass alike, as R2 does for a single take.
3. **File size.** Every MIDI pass is stored in the project; a long loop
   session can hold many. Keep-only-this-take is the way out; a count is shown
   in the chip.
4. **Capture on the audio thread.** More messages pushed when idle; bounded by
   the queue, counted when lost, run under the allocation guard.
5. **A buffer that listens to a keyboard** is a privacy-sensitive thing to
   keep: memory only, 10 minutes, a switch, and documented.
