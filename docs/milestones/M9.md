## 1. Decisions the evidence settled

| # | Decision |
|---|---|
| D1 | Recorded files are 32-bit float WAV at the device rate, one file per take per armed track. A stereo input is one stereo file |
| D2 | The audio thread only copies input into a ring, and a disk thread writes. An overrun is counted and padded, and the audio thread never blocks |
| D3 | A take file is valid at every moment: its header is rewritten about once a second, and a sidecar drives recovery |
| D4 | Drift between separate input and output devices is corrected with rubato's `Slip`. ASIO needs none |
| D5 | Export is `render_source` of the project through a converting, dithering writer. Real-time export is driven by the device and gives the same file |
| D6 | Renders follow the project sample rate (R4, P1 A). `Project.sample_rate` already existed, so this needed no new field |
| D7 | No modal dialogs. Export, Project settings and the media pool are ordinary windows or panes, and progress and cancel live in the task area |
| D8 | macOS and Linux input are compile-only until hardware exists (owner, 2026-10-06) |

## 4. Built slices

### R2 — Audio recording

- **Capture.** `InputPlayer` capture routes push chunks into a preallocated
  SPSC ring that holds 8 s of 32 channels. A full ring drops the chunk, counts
  an overrun, and the gap is padded so the take stays aligned.
- **Writing.** A worker writes one take file per track into `Recordings`.
  Save copies it to `Samples/Recorded`.
- **Placement.** At Stop, each take is placed at the first heard sample, less
  the input and output latency and the manual offset
  (`AudioSettings.record_offset_ms`).
- **Undo.** `Document::record_audio_take` is one undo step, and it replaces
  what the take covers.
- **Recovery.** A sidecar `<take>.take.json` lets recovery repair the take and
  put it back with the session's autosave.
- **Format.** There is no format change.
- **CI.** The macOS CI follow-up on PR #63 led to ADR-0103: callback-side
  polling within the audio deadline.

### R2b — The loopback helper

- **Card.** Measure… beside the recording offset unfolds a card in the
  Latency section. It has Cable from (an open output pair) and to (an open
  input), a strip of the returned clicks, the result, and Use +x ms. The
  command "Measure recording latency…" opens it.
- **Measurement.** It runs after the engine in the device callback
  (`lumen_engine::loopback`): five 256-step clicks at −12 dBFS, 0.3 s apart,
  with everything else silenced, while the input is kept beside them.
  Output and input count the same callback frames, so the delay found is the
  shift recording needs.
- **Analysis**, off the audio thread: each click is cross-correlated over
  0 to 250 ms. All five must agree within 2 frames. Silence, noise and
  disagreement are refused, each with what to check.
- **Offset.** Use sets (measured − reported) as the recording offset and
  remembers the driver, device, rate and buffer. A hand-typed offset forgets
  them. A different setup shows a hint to measure again, and a result
  measured before the device, rate or buffer changed is not offered.
- **Tests.** Unit tests cover the analysis (delays, noise, a polarity flip,
  silence, disagreement) and the player. The allocation guard covers the
  audio side. Five E2E scenarios use a cable scripted on the fake device.
- **Format.** There is no project format change. The settings gain
  `offset_measured`, an added field.

### R3 — Takes and Capture MIDI

**Model.** `Clip.takes: Option<Takes { active, count, others }>` (format
v31). A pass is one of:

- `Pass::Audio { offset, audio_phase_seconds }`, a window on the same file;
- `Pass::Midi { notes, events }`.

The clip's own content is the active pass, so the engine sees an ordinary
clip.

**Takes menu and chip.** The Takes menu and an n/m chip work with the
commands:

- `clip.take_next` and `clip.take_previous`;
- `clip.take_keep`;
- `clip.take_extract` (audio only).

**Edits and takes.** Split, trim and slip carry the other passes with the
cut. Reverse, unloop and MIDI join settle the clip: it keeps the take it
plays and says so in a notice.

**Capture MIDI.** Shift+F9 runs it. The engine tags messages
`Heard::{Recording, Playing, Stopped}`. The app keeps the last 10 minutes,
at most 20,000 messages, in memory only. Its switch is in the record menu.
A capture uses Overdub placement and is one undo step.

**Loop takes.** After the owner's runs, one model replaced four separate
fixes (ADR-0104, last section):

- `record_span` fixes what a take replaces.
- `loop_passes::cut` cuts every pass by one rule.

### R4 — Project lifecycle

- **Save a copy** is self-contained: every file is copied in, and the open
  document is untouched.
- **Collect and save** copies under temporary names and writes the project
  file last. Esc stops it with nothing changed, and it never deletes a
  source. Neither is an undo step.
- **Templates** live in `Documents/Lumen/Templates/<Name>/` and are opened with
  New from template. They are not renamed or deleted inside Lumen.
- **Revert** works as chosen in P2.
- **Project settings** covers rate, pan law, crossfades, new-track colour and
  notes. Format v32 adds the notes and the colour. Tempo and meter stay out of
  this window.
- **Rates.** A new project takes the device's rate. Join, bounce and freeze
  render at the project rate, decoding again only when it differs from the
  device's rate.
- **After MT-PROJ-1 run 1:**
  - projects and templates moved to `Documents\Lumen` (`Launch::user_dir`);
  - the app menu was grouped (ADR-0105 item 5b).

### R4b — Media pool

- **Project media tab.** The browser's Project media tab lists every audio
  file with its state.
- **Relink.**
  - Locate checks channels, rate and length. A different length needs a
    second click.
  - Search a folder shows its matches before Apply. It leaves ambiguous items
    alone and stops at 200,000 entries.
  - Relink changes where files are, not the song, so it is not an undo step.
- **Remove unused** is one undo step.
- **Clear…** moves leftover files to the system trash (`trash` crate, MIT)
  after a second press. Renders and Recordings are never cleared
  automatically.
- **Banner.** A banner with Relink… replaces the toast shown when a project
  opens with missing files.

### R5 — Export

**Window and scope.** The Export window opens with Ctrl/Cmd+Shift+E. It
exports:

- the project, the loop or the selection;
- the master or stems for tracks, groups and returns.

**Formats and processing:**

- WAV 16, 24 and 32-bit float, and FLAC 16 and 24 (pure-Rust encoder, licence
  checked);
- rate conversion, TPDF dither for integer files, peak normalize and tails;
- offline or device-driven real time;
- progress, cancel and a loudness report.

**Behaviour.** Export never changes the project or its history. A cancelled
or failed export leaves an existing file in place. Export choices are session
state, so there is no format change.

**Verification (2026-10-26):**

- **Windows:** 3,179 workspace tests passed (719 E2E, nine of them export
  workflows) and the 6 smoke tests passed.
- **Encoding:** 5 tests cover every format and depth, conversion,
  normalization, saturation, deterministic dither, a partial FLAC frame and
  cancel.
- **Callback golden:** 11,234 frames are identical to the offline render,
  including compensation and a trimmed tail. There are zero heap operations
  under the allocation guard.
- **Linux:** 3,174 passed and 1 failed: the existing `lumen-plugin-host`
  orphan-startup test (KNOWN_ISSUES).
- **Instruction gates:** all 13 passed. The largest change is project
  serialization at +1.69%.
- **After merging with R4b:** 3,217 Windows tests (723 E2E) and the smoke
  tests passed. The 9 export and 4 media-pool workflows passed on Linux.

Not run: real ASIO or WASAPI capture, external plugins, a long soak.
KNOWN_ISSUES listed the RAM use while encoding and the 4 GiB RIFF limit; R6
closed both.

### R6 — Disk streaming and the peak cache

**Stream files.** A WAV, RF64 or AIFF file in PCM or float at the device
rate plays from where it is, with positioned reads; memory maps are not used,
since a page fault on the audio side is blocking I/O. Any other file is
converted once, in the background, to a 32-bit float WAV in the cache, bit
for bit what loading it into memory gives. A cache entry is keyed by the
source's path, size, modified time and rate, so a changed file is converted
again. Peaks are kept beside each entry, so a reopened project shows its
waveforms without decoding.

**The audio thread** reads a fixed pool of 4,096-frame pages (96 MB,
allocated when streaming starts) and never waits. A clip whose next 40 ms
are not in memory glides out and counts one underrun. With its pages in, a
streamed clip renders bit-identical to the same clip in memory.

**The disk thread** plans from the clip list the engine plays, in this
order: the cue of a start, the next half second at the playhead, the rest of
two seconds ahead (wrapped into a playing loop), then the starts of the song
and the loop and each marker. Offline renders (bounce, join, freeze, export)
read their pages on the render thread, so they equal real time.

**Starts** (L A) are held until the next 140 ms at the new place are read,
for at most 150 ms. **Feedback** (D A): a Disk row ("12% · 0 late") and a
"Disk late" chip.

**Files without whole-file memory.** Export reads and measures loudness in
blocks; WAV writes RF64 past 4 GiB; reversed long files become stream files;
the atlas reclaims the old rate's peaks.

**Measured** (Windows 11, release, 64 stereo files of two minutes): opening
at 48 kHz took 0.67 s and 3,085 MB in memory; from disk it took 0.25 s and
170 MB, and 0.03 s with a warm cache.

**Soak.** 64 streamed tracks in real time at 128 frames, from a fake disk
with stalls, with loops and locates; it runs in CI's test step and asserts
zero late reads. Its CI failures (2026-10-29) were the disk thread's: a slow
plan, a writer scan per page, a cue cleared before the playhead moved, and
too small a margin after a start. All four were fixed in the product
(ADR-0109).

### R7 — Preferences, tap tempo and command coverage

Planned 2026-10-30 (owner: SP A, PW A with switches, TT A, End the only new
default key); built in five parts on `m9-s7-preferences` (ADR-0112).

- **Commands.** Loop, Metronome, Punch in and out, Go to end (End), Audio on
  or off, Next time format, Show or hide the browser, Solo or Cue, Add
  return and group track, Preferences and its pages, History and Tap tempo
  are commands, and the controls that did these things run them. A coverage
  test lists every transport-bar control and app-menu row with the command it
  runs or the reason it has none, read from what is drawn
  (`testing::coverage`).
- **The window.** One Preferences window: Audio, MIDI, Recording, Editing,
  Mixing, Plugins, Files and Appearance, a page list with a search that finds
  any setting by a word and outlines its row, folding into a page menu below
  560 pt. A change applies at once and is not an undo step; there is no
  Reset button.
- **New settings** (added fields; the settings version stays 1, hand-written
  values are brought to the nearest choice):
  - autosave every 30 s, 1 min or 2 min, at once (recording still hurries it
    to 10 s);
  - undo steps 1,000, 5,000 or 10,000, from the next project opened or made;
  - new audio tracks' monitoring and new MIDI tracks' instrument, for every
    way a track is made (add, device drop, audio and MIDI import);
  - the projects folder, where New, Open and Save as start;
  - the cache: its folder (a `Lumen cache` folder inside the one chosen, from
    the next start; the old one offered once for Clear), its limit (5 to
    100 GB) and Clear. Trim and Clear touch only the cache's own names in a
    folder it marked, which it does only to a new folder or one holding
    nothing but its names; an entry used in the last two minutes, or hit
    while Clear runs, is kept;
  - plugin folders can be removed, and blocked plugins are listed with Retry.
- **Tap tempo.** The Tap piece after the tempo, and the command. From the
  third tap the tempo is 60 ÷ the mean of the last four intervals, whole BPM;
  a stray interval (over 40% off) is ignored, two in a row restart the run;
  3 s without a tap, any other edit or another project ends it. A run is one undo step on the
  segment where it started; a frozen track refuses the first tap.
- **Deviations from the plan** (ADR-0112): new-track defaults are a document
  option set each frame rather than a parameter of `insert_track`; the
  standard cache stays where R6 put it.
- **Tests.** Unit tests for each setting, the cache's name filter and
  marker, the undo limit and the tap model; E2E for every page and searchable
  row, the new settings, the blocked list, the cache across a restart, tap
  tempo (exact times, one undo, a held key, a frozen track) and coverage.
- **Not verifiable here:** the real file dialogs, device changes on the
  owner's interface through the moved Audio page, and the feel of tapping by
  hand (MT-PREF-1).

### R7b — The first-run wizard (plan)

Planned 2026-10-31 on `m9-s7b-first-run`, cut from `main` after R7 merged.
CLAUDE.md §7 asks for a first-run wizard [M] that chooses and tests the
audio device and sets the plugin paths. **The owner took every
recommendation below** (2026-10-31, §2), chosen from specimens rendered
outside the repository.

**What a first start is like today.** Lumen opens an empty song on the
Windows default output (`Choice::Default`, WASAPI shared) and scans the
standard VST3 folders in the background. Nothing says that an ASIO driver
is installed, that the sound works, or where to add a plugin folder: those
are three levels down, in Preferences.

**Two existing faults the wizard depends on** (found in review, in
`docs/KNOWN_ISSUES.md`):

- Choosing a device of another driver model blocks the interface. Choosing
  ASIO in Preferences does this today. `Audio::apply` joins its lookup
  thread, and `AudioSystem::switch` waits up to 10 s for the handover, then
  joins the old control thread, all on the interface thread.
- A folder added while a scan runs is not scanned. `Plugins::rescan`
  returns at once while a scan is busy, and the running scan has already
  read its folders. On a first start a scan is always running, so the
  wizard would hit this every time.

#### The owner's choices

Each choice changes what the user sees, hears or does. The recommendation
is first in each list.

- **F, where the wizard lives** (specimens F A, F B, F C):
  - **A** (recommended): a welcome window, an ordinary `widgets::Dialog`,
    top-centre, over the empty song. It is 560 pt wide, or narrower when
    the window is. The song behind stays usable with the mouse, so nothing
    waits on the wizard. ✕, Esc and Skip setup close it and keep what is
    set.
  - **B:** a welcome screen that fills the window until Done or Skip. It has
    the most room for character, but the song cannot be seen or used until it
    closes.
  - **C:** no window. The empty arrangement's card becomes a "Get set up"
    checklist, with one row per step. Each row opens its Preferences page,
    and "Set up Lumen…" shows the card again. It is the lightest, but
    choosing a device happens one level away. S and M still apply: S sets
    the rows, and M is drawn small at the card's head.
- **S, the steps:**
  - **A** (recommended): three steps. Sound, Plugins, then Ready. Ready has
    a summary, a Look row (theme and UI size), Open a project… and Start
    making music.
  - **B:** two steps. Sound, then Plugins, and the window closes.
  - **C:** five steps, with Look and MIDI (controllers) as steps of their
    own.
- **T, what the sound check plays:**
  - **A** (recommended): Play test sound plays a soft chime once, about
    1.5 s at −18 dBFS peak. One note sounds on the left, one on the right,
    then one on both, while an L and an R light show which is sounding. This
    proves both speakers and their order. Pressing again restarts it.
  - **B:** the Preferences test tone as it is: a switch for a steady 1 kHz
    at −20 dBFS on every output until it is turned off.
  - **C:** one bar of the metronome (accented 1, then 2, 3 and 4) on both
    channels.
- **D, the driver Windows starts on:**
  - **A** (recommended): the Windows default output, so the first sound
    works at once. When an ASIO driver is installed, the Sound step offers
    it: "<driver> is installed. It records with less delay", with a Use ASIO
    button. With several ASIO drivers, the button is a menu of their names.
  - **B:** ASIO is chosen without asking when exactly one ASIO driver is
    installed, falling back to Windows audio if it will not start.
  - **C:** the step first asks "Speakers or headphones" or "An audio
    interface" on two cards, then shows the device rows for the answer.
- **P, plugin scanning:**
  - **A** (recommended): scanning starts at launch as it does now. The
    Plugins step shows the live progress. A folder added there is scanned
    as soon as the running scan ends, with "Waiting to check
    D:\…\VST3" shown meanwhile. Next never waits for a scan.
  - **B:** on the first start, scanning waits until the Plugins step is
    passed, so the folders are set first and scanned once. Skipping the
    wizard starts the scan at once.
- **M, character** (specimens M A, M B, M C):
  - **A** (recommended): Lumi, the approved anime mascot (`docs/brand/`),
    appearing only in this window and never in the working interface. Lumi
    waves on Sound. On Ready, Lumi celebrates when everything works, and
    looks curious when something still needs doing. Each pose is a 256 px
    PNG of about 80 KB, built into the binary.
  - **B:** the empty state's sunrise mark, rising once with a slow glow
    (still with Reduce motion), drawn in code.
  - **C:** type only, with the display title.
- **W, when the wizard opens:**
  - **A** (recommended): on the first start, until it is finished or
    skipped, and whenever it is asked for. "Set up Lumen…" is a new command,
    in the app menu under Preferences and in the palette.
  - **B:** as A, and also at any start where the saved audio device is
    missing. This is not recommended: the device notice already handles

- **X, where the two faults are fixed:**

#### The plan, as recommended

- **What counts as a first start.** A new settings field,
  `setup_done: bool`. It is an added field, so the settings version stays
  1. A file written before R7b has no such field and reads as done, through
  a field-level serde default of `true`. With no settings file, the
  defaults have it `false`. `settings::load` also sets it `true` when it
  moves an unreadable or newer file aside, because that user is not new and
  the existing warning already says what happened. It becomes `true`, and
  the settings are written at once, when the wizard closes in any way:
  Start making music, Skip setup, ✕ or Esc. Until then, quitting brings the
  wizard back on the next start, even if a device or a folder was chosen
  and saved meanwhile. The wizard then opens on Sound again, with what was
  chosen kept (the step itself is not saved).
- **Where it does not open.** The test harness, `--screenshot` and
  `--smoke-test` never open it unless `--first-run` is given. In safe mode
  it opens, and its Plugins step says that plugins are off for this run.
  Opening a project from the file manager on a first start opens both the
  project and the wizard, because the window is not modal.
- **Device changes stop blocking the interface** (X A: the first fix
  branch). The lookup, `AudioSystem::switch` and its handover run on a
  worker thread that owns the `AudioSystem` while it works, and the result
  comes back as an event read each frame. Meanwhile `Audio::changing()`
  says what is happening, as it does for a change within a driver model.
  The device controls in the wizard and on the Audio page are disabled, so
  only one change runs at a time. The worker keeps the interface
  responsive; it does not make a driver answer. What each failure leaves:
  - **The new driver refuses to open** (an error comes back): the setup
    before is restored, as today.
  - **The old audio thread does not hand over within 10 s** (the existing
    timeout): the engine's callback is still held by that thread, so it
    cannot be restored. Audio stays off and the row says so in full:
    "<driver> did not let go of the audio. Save your work and restart
    Lumen." The song, editing and autosave carry on.
  - **Closing the old driver or opening the new one never returns** (no
    deadline exists in `supervisor.rs`, and none can be forced on a
    driver's own call): after 10 s the row says "<driver> is not
    answering", with the same advice. The worker stays waiting.
  - **Quitting** never waits on the worker: the window closes, the project
    is saved or asked about as usual, and the process exits.

  Tests use a test backend with three faults: opening refused, opening
  delayed by 3 s, and a handover that never comes. E2E shows that frames
  keep coming in each, that a second choice made meanwhile is refused, that
  the refused open restores the setup before, that the two hangs show their
  messages after 10 s, and that quitting with a worker still waiting exits.
- **A folder added during a scan is scanned** (X A: the second fix
  branch). `Plugins::rescan` asked for while a scan runs is remembered, and
  runs with the folders as they are then once the scan ends or is
  cancelled. In safe mode nothing is scanned, as now. E2E covers adding and
  removing a folder during a scan and during Cancel.
- **The window** (`app/welcome.rs`, with its state on `App` as Preferences
  has).
  - **Head.** The step pills ("1 Sound", "2 Plugins", "3 Ready") stand in
    the title row, with ✕ at the right. `Dialog` gains a head of the
    caller's own (`Dialog::head`), keeping ✕ and the lip, so this stays one
    shared widget.
  - **Pills.** Every pill can be clicked. A pill shows ✓ only for a step
    whose state is good, and a warning mark (shape and colour) for one that
    needs something. A pill shows nothing for a step not yet seen.
  - **Display title.** Each step has a display title, in `fonts::display`
    at a new `theme::size::DISPLAY` of 24 pt. This is the first use of the
    display style, and `space::XL` and `space::XXL` join `theme::space`, as
    DESIGN.md §4 and §5 foresaw.
  - **Footer.** Skip setup (or Back), a hint "Tab moves between controls ·
    Esc skips", and the window's one filled button, Next.
  - **Size.** The width is the smaller of 560 pt and what the window
    leaves, worked out as Preferences does (`preferences::fit`). The body
    scrolls between the head and the footer, so the pills and Next are
    always reachable. Below 480 pt, Lumi is hidden and the title wraps.
- **Keyboard.** The wizard joins `App::window_open`, so Shift+Tab moves
  focus inside it and Enter is not sent to the song. When a step opens,
  focus goes to Next.
  - **Tab and Shift+Tab** walk the step's controls from the top, then Back
    and Next.
  - **Enter and Space** activate the focused control, as everywhere in
    egui. Enter means Next only when nothing has focus and no menu is open.
  - **Esc** closes an open menu first, then leaves a field, and only then
    skips. `Dialog` gains `Dialog::esc_to_caller` so the wizard decides,
    and the other windows keep their current behaviour.
  - **Other shortcuts** (Space to play, the palette) keep working while the
    wizard is open, as they do with Preferences open.
  - When the wizard closes, focus returns to the song.
- **Sound.** The Device section of the Audio page is moved into a function
  that the page and the wizard both call (`preferences::audio::device_rows`),
  so a device is chosen, applied, refused and restored the same way in both
  places.
  - **The ASIO offer** appears when the ASIO catalog lists a driver and the
    driver in use is not ASIO. It applies through the same `Action::Apply`.
  - **Play test sound** is an ordinary raised button, with the L and R
    lights and an output meter beside it, and a hint: "Nothing? Check the
    volume, or choose another device." Once the device runs, a latency line
    shows the round trip.
  - **Each state is said in full, with what to do:**
    - Running: the step's ✓.
    - Switching: "Switching to <driver>…" with the controls disabled.
    - No output found: "No sound output was found. Plug one in and press
      ⟳, or continue without sound." Next stays enabled.
    - Driver busy, refused or missing: the driver's message, then "Back to
      Windows audio" or "Try again".
    - Lost: "<device> was disconnected. It reconnects when it is back."
    - Audio off: "Audio is off" and an Audio on button.
- **The sound check** (T A, `lumen-engine`).
  - **The sound.** `Command::SoundCheck` starts a chime made in the engine
    like the metronome: three sine notes with a short attack and an
    exponential decay, at frames 0 (left), 0.5 s (right) and 1.0 s (both),
    at the device rate, on the main pair. It plays whether the song is
    playing or not.
  - **Real time.** It allocates nothing and takes no locks. While it is
    idle, its rendering is a skipped branch.
  - **The lights** read which part is sounding from an atomic that the
    engine publishes, so they follow the sound rather than a timer in the
    interface.
  - **What ends it:** Stop, Audio off and a device change.

  folder and scan are shared in the same way (`plugins_folder_rows`).
  - **The step adds** the scan's progress ("Checking plugin files: 17 of
    40", from `Status::Scanning`, which counts modules), the plugins ready
    to use ("23 plugins ready", counted from the catalog without the
    built-in devices), the blocked count with a link to the Plugins page,
    and Cancel.
  - **States:**
    - Reading the list: `Loading`.
    - Could not start: `Failed`, with its message and Retry.
    - Stopped: "17 of 40 checked", with Rescan.
    - The scanner program missing: its message, which names the command to
      build it.
    - Safe mode: "Plugins are off for this run", with no ✓.
- **Ready.** The summary says what is true. Sound gives the driver and the
  device, the rate and buffer, and the round trip, or "No sound: choose a
  device on the Audio page". Plugins gives those ready and blocked, or
  "Still checking" or "Off for this run". The title is "You are set" only
  when Sound and Plugins are good, and otherwise "Almost set", followed by

  Open a project… (the existing command) and Start making music, which

#### MT-FIRSTRUN-1 (the owner, on the Focusrite)

This test uses the real audio device on purpose. Every per-user file goes
to a new scratch folder, and `%APPDATA%\Lumen` is never touched. First,
once (the scanner and the plugin host must be built beside Lumen):

```powershell
cargo build --release -p lumen-plugin-host
$dir = "$env:TEMP\lumen-first-run-$(Get-Date -Format yyyyMMdd-HHmmss)"
New-Item -ItemType Directory -Force $dir | Out-Null
```

Then start Lumen, now and again in step 5, with this line only:

```powershell
cargo run --release -p lumen-app -- --settings "$dir\settings.json" --autosave-dir "$dir\autosave" --crash-dir "$dir\crash" --user-dir "$dir\user"
```

1. The window opens on Sound, with the Focusrite's ASIO driver offered.
2. Play test sound on Windows audio: left, then right, then both, in the
   right speakers.
3. Use ASIO. While it switches, the window still answers (drag it, or open
   a menu behind it). Then the round trip shows, and the test sound plays
   through the interface.
4. On Plugins, add a folder while the first scan is still running, and see
   it checked after. Go to Ready, pick Light and 150%, and press Start
   making music.
5. Close Lumen and start it again with the launch line. The wizard does not
   open, and the ASIO device, the folder, the theme and the size are kept.
6. "Set up Lumen…" from the palette opens the wizard again.

#### Risks

- A driver that never answers cannot be recovered from inside Lumen: audio
  stays off until a restart, and the row says so. The fix (X A) only keeps
  the interface responsive and the work safe. A real hanging driver is not
  available to test, so the faults are simulated by the test backend.
- The chime at −18 dBFS can be loud on monitors turned up high. It is short
  and fades in, and the level is a constant, so it is easy to change after
  MT-FIRSTRUN-1.
- The slice grew in review: two faults are fixed before it. Without them,
  the wizard's main action (Use ASIO) freezes the window.

## 5. Gates

- **Usual gates:**
  - fmt;
  - workspace clippy with `-D warnings`;
  - workspace tests;
  - E2E and smoke tests;
  - macOS cross-clippy.
- **Engine and project changes** also run the WSL mirror and the performance
  gate, which fails at +2%.
- **Real-time paths** run under the allocation guard and RealtimeSanitizer:
  - the capture copy;
  - the monitor path;
  - the disk reader's hand-off.
- **E2E recording scenarios** use the fake backend with a scripted ramp input.
- **Persisted fields:** each new one bumps the format, with a migration and a
  frozen golden.
- **Owner's hardware:** ASIO and WASAPI input, round-trip latency, drift and
  monitoring through effects need the owner's Focusrite. The cloud container
  verifies the logic and the fake-backend paths only.

## 6. Open risks

1. **Latency is unmeasured on real hardware.** R2b measures the round trip
   through a cable; its first run on the Focusrite is MT-REC-5.
2. **Streaming underruns** can happen at small buffers on slow disks. R6
   mitigates this with a read-ahead sized in seconds, files under 30 s kept
   in memory and a visible underrun counter. Without a per-clip switch (M B),
   a clip cannot be pinned in memory: if underruns show, the automatic rule
   is widened rather than adding a control.
3. **Offline and real-time output can differ** for plugins that behave
   differently offline. Real-time export is the fallback.
4. **Licences:** the ASIO SDK agreement is still open with the owner and must
   be settled before any distribution.

## 7. Alternatives rejected

- **Recording through the clip player's memory path:** a long take needs
  unbounded memory, and a crash loses it all.
- **One file for all armed inputs:** a take could then not move between
  tracks.
- **Streaming first:** it delays the owner's priority and doubles the
  real-time risk.
- **Revert as one undo step back to the saved state:** changes made inside a
  plugin's window would survive it.
- **Clear that erases files for good:** it cannot be undone, which breaks
  priority 1.
- **Streaming that never waits on a start** (L B): the first beat of a drum
  loop could be missing while MIDI already plays.
- **One ring per streamed clip:** loops and markers would need rings of
  their own, and a clip list change would allocate.
- **Converted copies inside the project folder** (C B): projects grow by a
  float copy of every converted file.
- **R6 and R6b as two slices** (S A): the owner chose one slice.
