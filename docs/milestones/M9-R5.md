# M9 R5 — Export

Branch: `m9-s5-audio-export`, cut from `origin/main` at `335b3ecb`.
R4 project lifecycle is merged. R4b media-pool work is independent and is
not a dependency of this slice. Format starts at v32.

## Scope

Implement the approved X1 A Export window, opened from the app menu and
command palette with Ctrl/Cmd+Shift+E. Export the whole project, loop or
time selection, as a master mix or separate track, group and return stems.
Use the existing design-system window and controls.

Write WAV (16-bit, 24-bit, 32-bit float) and FLAC (16-bit or 24-bit), with
sample-rate conversion, optional TPDF dither for integer files, peak
normalization, optional effect tails, progress, cancellation and a final
loudness report. Export never changes project content or undo history.
Rendering and file operations run on workers; plugins use isolated hosts.
Existing destination files survive failed or cancelled renders.

## Work and verification

1. Inspect rendering, routing, plugin-state capture and the live output
   path. Settle stem signal paths and real-time capture before integration.
2. Add encoding and conversion with deterministic numeric and decoded-file
   tests. Check the pure-Rust FLAC encoder's license and API at its source.
3. Build export rendering and the window. Snapshot the project and plugin
   states so concurrent editing cannot alter the running export.
4. Add user-driven E2E scenarios, golden audio comparisons, routing and
   cancellation checks, including offline versus real-time output.
5. Run fmt, workspace clippy and tests, E2E, real-binary smoke and applicable
   platform/performance gates. Inspect both themes at 100/150/200%.
6. Update the ADR, architecture, progress, manual test and handoff with
   measured outcomes and explicit limits. MT-EXPORT-1 remains owner-run.

Disk streaming, preferences, browser audition, media relinking/purge and
icons remain in their assigned slices. Export choices initially live in
session state; no project-format change is needed for export itself.
