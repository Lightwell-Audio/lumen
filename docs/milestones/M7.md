# Milestone 7 — Automation, Editing & Render: plan

**Status.** Part A (automation and envelopes, A0 to A8) and Part E slices E0
to E6 (editing and render) are built and merged (PR #40 to #58).

Part E was planned as a separate milestone, "M7b", from 2026-10-19 until
2026-10-29, when it was folded back into this plan. Branch names, code
comments and older records still say M7b. The slice names E0 to E6 are
unchanged.

The manual tests are in [manual-tests/M7.md](../manual-tests/M7.md).
MT-EDIT-2 and MT-EDIT-7 are pending. The owner has not yet approved the
milestone.

**E7 (the audio clip editor) and E8 (warp and time-stretch)** were added on
2026-10-29 at the owner's request (§5). Neither has started.

**Goal (CLAUDE.md §9 steps 7 and 8, §5, §6.5, §6.6).** Everything that has a
value can be automated, recorded and mapped to a controller. Clips carry
envelopes. A professional workstation's editing tools work on clips and time
ranges.

**Exit criterion.** A user can do all of the following, then save, reopen
and hear the same result:

- automate a track's volume and a hosted plugin's filter;
- record a fader move in Touch and Latch;
- map a controller knob;
- change tempo and time signature along the song;
- give an audio clip gain and pan envelopes;
- split and rejoin clips with no audible change;
- crossfade two clips;
- consolidate and bounce a track with effects;
- freeze a track.

E7 and E8 are not part of this exit: the owner may approve M7 without them,
and each closes with its own manual test (MT-EDIT-8, MT-EDIT-9).

**Requirements covered:** CLAUDE.md §5 (tool model), §6.2 (clip properties,
crossfades, and warp with E8), §6.5, §6.6, MIDI learn (§6.3, moved here on
2026-10-13) and the matching rows of §7.

## 1. Decisions the evidence settled

Each has an ADR with the reasoning and the code pointers.

- **D1. Data shape** (ADR-0081). Lanes are built from `lumen_core::automation`
  `Point { at: Ticks, value, shape }` with Step, Linear or Curve segments, and
  are simplified for freehand drawing and recording.
  `Track.automation: Vec<AutomationLane { target, lane, enabled }>`. A target is
  volume, pan, trim, mute, a send or a device parameter. Values are in the
  target's own units, so a linear volume segment is linear in dB.
- **D2. Ownership.** Lanes belong to the track that owns the target. They move,
  copy and delete with their track or device. A lane whose target is gone is
  dropped on load.
- **D3. Time.** The model keeps ticks and the engine keeps samples. The UI
  bakes lanes against the tempo map, and a tempo edit rebuilds the plan.
- **D4. Accuracy.** Points are sample-exact. Inside a segment the value is
  evaluated every 32 frames. An automated value bypasses the 20 ms glide.
- **D5 and D7. Display and override.** Controls show `Lane::value_at` at the
  playhead, computed in the UI. An override is session state (ADR-0086).
- **D6. Plugin parameters** travel as sample-positioned points on the existing
  `ParamQueue` wire. Overflow is thinned and counted (ADR-0084).
- **D8. MIDI learn** taps the live feed. Mapping happens in the app, never on
  the audio thread (ADR-0088).
- **D9. Tempo and meter lanes** are views over `Project.tempo` and
  `Project.meter` (format v24, ADR-0089).
- **R1. One render core.** A device-free driver runs on a worker and writes
  through a hand-written WAV writer (ADR-0095). FLAC came with M9 R5's export
  (ADR-0107).
- **R2. Offline plugins.** A spike proved that hosts render offline
  repeatably, so the real-time fallback (F1) was never needed (ADR-0096).
- **Seamless joins.** Clips cut from contiguous source play as one clip. A
  null test proves it (ADR-0092).

**Built differently from the plan**

- **Reverse** plays reversed copies of files made on a worker, with no engine
  change (ADR-0093).
- **Join** in E1 did not close gaps in audio until E3 arrived.
- **Consolidate:**
  - It renders with bare outer ends.
  - Its files go to a `Renders` folder that Save copies into
    `Samples/Rendered`.
  - It wrote at the device rate until M9 R4 made renders follow the project
    rate.
  - Consolidating a time range is not built (KNOWN_ISSUES).
- **Bounce:** Replace with effects falls back to a new track when the span is
  not the whole track or a clip is locked (ADR-0097).

## 4. Validation

These apply to every slice, E7 and E8 included.

- Run the usual gates:
  - fmt;
  - workspace clippy with `-D warnings`;
  - workspace tests;
  - the E2E suite and the six smoke tests;
  - macOS cross-clippy.
- For engine and project changes, also run the WSL mirror and the performance
  gate (it fails at +2%).
- Real-time paths run under the allocation guard and RealtimeSanitizer.
- Each new persisted field bumps the format, with:
  - a migration;
  - a frozen golden;
  - an entry in `history::unchanged`.
- Render and playback changes need golden renders. Split, join and
  consolidate of unprocessed audio must null against the original.
- Show visual and gesture choices as rendered specimens before building.
- Check shots in both themes at 100, 150 and 200%.

The cloud container cannot verify real controllers, installed plugins, real
devices or macOS. These are covered by the owner's MT runs, and each slice's
report says what it left unverified.

## 5. Planned: audio clip editor and warp (2026-10-29)

The owner asked for two things: a professional-grade view for audio clips,
and a place for warp. Both belong in this milestone, for three reasons:

- CLAUDE.md §9 lists warp under "editing power tools".
- The deferrals P1 and Y1 wait on warp.
- Warp markers need an editor to live in, so E7 comes first.

Neither slice blocks M9's remaining slices, and the owner decides when they
run.

**Today.** An audio clip's Clip tab shows the clip card's rows beside a
static wave of the clip (`app/detail.rs` `audio_clip_view`, ADR-0108 DP1).
That wave:

- is painted column by column on the CPU;
- cannot be zoomed or edited;
- shows nothing of the source outside the clip.

Arrangement waves come from the GPU peak pyramid (ADR-0027). `lumen-media`
resamples (rubato) but has no time-stretch.

### E7 — Audio clip editor (M)

The Clip tab becomes the audio counterpart of the piano roll.

- **Wave.**
  - The whole source file is drawn from the arrangement's peak pyramid.
  - The clip's window is bright and the rest is dimmed.
  - At the deepest zoom it shows individual samples.
  - A ruler shows bars and time.
  - Zoom and scroll use the note editor's gestures.
- **Handles on the wave.** Trim edges, fades and their shapes, the gain line,
  the gain and pan envelopes, and loop length. These are the arrangement's
  own `Document` edits, so the clip and the editor always agree.
- **Navigation.**
  - The playhead and the edit cursor.
  - Dragging the source outside the window slips the clip.
  - Snap follows the grid, with Alt to bypass it.
  - An optional snap to zero crossings.
- **Properties.** The properties column is regrouped from the design system's
  pieces into four sections:
  - Clip;
  - Fades;
  - Processing: reverse, polarity, normalize;
  - File: format, rate, channels, length, size, path, missing state, Reveal.
- **Owner choice before building:** the layout, shown as rendered specimens.
  The options are the wave above the properties, beside them, or the
  properties in a strip.
- **Pass condition.**
  - Every edit is one undo step and matches the same edit made in the
    arrangement.
  - The view meets the frame budget with a one-hour file at every zoom.
  - The accessibility, Tab-order and shot checks pass.
  - There is no format change.

### E8 — Warp and time-stretch (L, after E7)

- **Engine.** A real-time-safe time-stretch and pitch-shift engine in
  `lumen-media` and the clip player. It has quality modes for rhythmic,
  melodic and polyphonic material.
  - The library is the first owner choice (TS1), after a quality comparison
    by ear. It must be compatible with Lumen's GPL-3.0-or-later licence
    (ADR-0039); any other terms go to the owner (CLAUDE.md §3).
- **Warp.** Clips follow the project tempo, which closes the KNOWN_ISSUES
  row from 2026-10-07. Warp markers are edited in the E7 editor and on the
  clip. Transient and tempo detection run on a worker.
- **Pitch.** The static clip pitch (Y1, [M]) and the audio pitch envelope
  (P1) use the same engine.
- **Audio quantize.** Audio quantize through warp markers ([S], §6.3) is in
  this slice only if the owner wants it here.
- **Format.** A format bump stores the warp markers, the mode and the pitch.
- **Pass condition.**
  - A clip that is not warped plays bit-identical to today.
  - A warped clip renders the same offline as in real time.
  - The engine path allocates nothing.
  - The performance gate holds for clips that are not warped.

## 6. Open risks

1. **Recorded timing on real hardware.** The accuracy of recorded points and
   mapped controllers has only been measured on the test device.
2. **Long lane passes.** A long pass is written in parts every 5 s, and
   another edit landing between two parts splits its undo step
   (KNOWN_ISSUES).
3. **E8's engine.** It is the largest real-time addition since plugin hosting,
   and the licence choice can rule out the best candidates. TS1 must be settled
   before any code is written.
4. **E7 at scale.** A source can be hours long. Draw only what is in view
   (CLAUDE.md §12).

## 7. Alternatives rejected

- **Automation:**
  - lanes in a project-level list keyed by target (dangling targets);
  - points stored in samples (a tempo edit would move every point);
  - normalised values for every target;
  - mapping inside the engine;
  - one value per block for plugins;
  - a lane as its own row, or a tabbed panel (the L1 specimens not chosen).
- **Editing:**
  - a new encoder dependency in M7;
  - bouncing every track through the live engine;
  - consolidated files written beside their sources.
