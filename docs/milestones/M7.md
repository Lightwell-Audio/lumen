# Milestone 7 — Automation, Envelopes & Advanced Editing: draft plan

**Status:** Draft, 2026-10-19. **Not approved and not started.** No code has
been written. It waits for the owner's sign-off of M5 and M6 (the reports are in
`docs/PROGRESS.md`) and for the owner's choices below.

**Goal (ROADMAP §7):** everything that has a value can be automated and
recorded, clips carry envelopes, and the editing tools a producer expects
(split, join, consolidate, ripple, crop, bounce, freeze) work on clips and time
ranges.

**Exit criterion:** a user can automate a hosted plugin's filter and a track's
volume, record a fader move in Touch and Latch, split and consolidate clips,
bounce a track in place, save and reopen, and hear the same result.

Requirements covered: CLAUDE.md §6.5 (automation and envelopes), §6.6 (editing
actions), MIDI learn with a mapping list (§6.3, moved here by the owner on
2026-10-13), the tool model (§5), and the matching rows of §7. Rows tracked
for M7 in `docs/PROGRESS.md`: split, join, consolidate, crop, loop/unloop,
nudge, ripple and insert silence completion, automatic crossfades, reverse,
normalize, polarity, select invert/in track/to start/to end, the drag-to-cut
gesture, and the tool model.

## 1. Starting point

- M6 supplies the parameter interface: a hosted plugin's parameters are listed
  with values, the project holds an overlay of values (format v19), and a
  plugin's own gesture arrives as begin, perform, end (ADR-0076). Hosted
  parameter changes reach the host through the shared-memory link.
- `lumen_core::curve` holds free fade curves (ADR-0031), named as the model
  automation reuses.
- The engine already glides mixer levels over 20 ms and crossfades plan swaps.
  It has no per-sample parameter timeline.
- Offline rendering does not exist yet. The host exposes an offline mode for
  M9, but export is M9.
- A tempo map exists (`Project::tempo`) and there is one time signature.
- M6 is not signed off (see the status above), and ADR-0069's callback wait is
  on trial. A slow plugin block must not stall a lane's timing.

## 4. Validation and records

- Each slice ends with the E2E suite and the six smoke tests (ADR-0029), and
  adds scenarios for what it delivered. E2E checks levels by waiting for what
  the engine answers, never a fixed time.
- New persisted fields bump the `.lumen` format version with a migration and a
  golden fixture. `history::unchanged` lists every new field.
- Run the WSL performance gate for engine work. The gate fails at +2%.
  Lane evaluation must cost nothing when a project has no automation.
- Measure frame time with 200 tracks and visible lanes at 100, 150 and 200%
  scale in both themes, and idle CPU.
- Update PROGRESS, DECISIONS, ARCHITECTURE, KNOWN_ISSUES and the handoff
  in `CLAUDE.md` after each slice. Hardware and plugin cases the cloud
  container cannot run are named as unverified.
- Documentation follows the owner's naming rule: no third-party product names
  as references or examples; anonymous labels for external plugin records.

## 5. Risks

1. **Plugin automation timing** rides on ADR-0069's callback wait, which is
   still on trial. If its measurements fail and the pipelined path replaces it,
   A2's sample positions shift by a block and must be compensated.
2. **Bounce and freeze** need an offline renderer that does not exist. E4 A
   puts M9's export path into M7 early; that is the right place to find out if
   hosted plugins render the same offline as in real time.
3. **Pitch envelopes** need a stretch engine (A5).
4. **Lane drawing cost** with many points is unmeasured. The piano roll's
   per-surface GPU layers are the model to follow.
5. **MIDI learn** can only be tested here with a fake port. Controller
   hardware is the owner's.
6. **Scope.** This is the largest milestone so far. If the owner prefers,
   slices 5 to 7 can move to their own milestone and M7 can end at slice 4.
