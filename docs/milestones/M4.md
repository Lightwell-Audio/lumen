# Milestone 4 — Mixer, Routing & Groups: plan

**Status:** Approved 2026-10-09 by the owner, with Ableton's solo as the
default and the UX pass on hints first (slice 0). Pan law: −3 dB constant
power by default (the proposal; the owner did not choose otherwise).

**Goal (ROADMAP §4):** make the arrangement capable of real production
work. Channel strips, faders, pan, mute and solo, input and output
routing, sends, return tracks, the master track, sidechain routing, group
tracks (nested), inline meters, the mixer panel, cue and preview, and the
foundation of automatic delay compensation. The routing graph is part of
the engine, not of the UI.

**Exit criterion:** a multi-track project can be routed through groups,
returns and the master bus, with predictable solo and mute behaviour.

Requirements covered: CLAUDE.md §6.1 (group tracks; track routing,
polarity, monitor and inline fader and meter), §6.7 (mixer, routing and
grouping), the §7 "Mixer and routing" row, and two items deferred to M4:
the metronome's output routing (M2) and group folding and dragging tracks
into groups (M3, ADR-0025).

## 1. Starting point (inspected 2026-10-09)

| Item | Finding |
|---|---|
| Engine | `lumen-engine` (about 2,400 lines) plays one list of clips into one stereo bus. A track's volume, pan, mute and solo are baked into each clip's level, which glides over 20 ms. There are no buses, sends or meters per track. Clip lists swap in without real-time allocation and go back to the UI thread to be freed. |
| Model | `TrackKind` already has Group, Return and Master, and `Track` has `parent`, `gain_db`, `pan`, `mute`, `solo` and `devices`. Nothing routes on them: groups and returns can be added from the menu but do nothing. There is no master track in projects, no sends and no outputs. Format v6. |
| App | Track headers have volume and pan sliders and mute, solo and arm (ADR-0025). The detail panel has an empty Mixer tab. Commands, palette and menus come from one table (ADR-0033), so new mixer actions are rows there. |
| Devices | The device selector chooses active output channels with names (M2), so hardware output pairs exist to route to. |
| Gates | Instruction-count gate in CI (+2%); frame-time benchmark by hand; real-time safety under the allocation guard and RTSan. |

## 2. Risk register

| ID | Risk | Impact if late | Addressed by |
|---|---|---|---|
| R1 | The graph costs too much on the audio thread at 64 tracks with groups and sends. | Misses the quality bar (under half the budget at 128 samples, 48 kHz) | Slice 1: a flat processing plan compiled off the audio thread, buffers preallocated, a 64-track routed scenario in the performance gate from the first slice |
| R2 | Swapping the graph while playing clicks, drops a block, or allocates. | Glitches while editing routing | Slice 1: plans swap at a block edge with a short crossfade, the old plan goes back to be freed; tests under the allocation guard; golden renders across a swap |
| R3 | Solo with groups, returns and sends behaves unexpectedly. | Users hear the wrong thing; trust lost | Slice 4: solo rules as a pure function with a table of cases, reviewed with the owner before building the UI |
| R4 | Routing cycles (a group into its own child, a return feeding itself). | Feedback or a hang | Slice 2: validation refuses cycles in `Document` methods and at load; the UI never offers a choice that would make one |
| R5 | Meters repaint the UI all the time. | Idle CPU rises | Slice 5: meters repaint only while a level moves, decay to rest, and stop; idle repaints measured as now |
| R6 | Delay compensation has nothing latent to test until plugins (M6). | The foundation is wrong when M6 arrives | Slice 6: a synthetic latent test node in the engine; tests that paths line up sample for sample |
| R7 | The mixer panel crowds the 960 × 540 minimum window. | Layout breaks at small sizes | Slice 5: strip widths from the design system, a horizontal scroll, specimens at 100% and 200% first |

## 3. Slices

Every slice ends with E2E scenarios for what it delivers, the smoke
tests, and a manual test (MT-MIX-*). New visual designs (strips, meters,
group headers) are shown as rendered specimens first.

### Slice 0 — The UX pass on hints (owner decision, 2026-10-08 and 09)
- An inventory of every drag hint, tooltip, caption and status line, with
  what each says and when it shows.
- Behaviour should come across without reading much: cursors, handle
  shapes and motion first, text last. Proposals shown to the owner as
  rendered specimens before building; then hints cut, shortened or
  replaced, and one rule for when text appears (DESIGN.md).
- **Pass:** the owner's manual test (MT-APP-17); E2E scenarios that relied
  on hint text updated; no workflow loses its discoverability (tooltips,
  menus and the palette still name every action).

### Slice 1 — The mixer graph in the engine
- Each track becomes a node: its clips play into the track's bus, then
  input trim, polarity, volume, pan, mute, sends and an output. Groups
  sum their children; returns take sends; everything ends at the master.
- The UI thread compiles the project's routing into a flat processing
  plan (an order with preallocated buffers); the audio thread swaps plans
  at a block edge and sends the old one back to be freed. Levels and pans
  change through smoothed parameters, as clip levels glide now.
- Track levels move out of the clip list into the track nodes.
- **Pass:** golden renders (a group equals the sum of its children; a
  muted track is silent; a send at 0 dB doubles into a return), zero heap
  operations while playing and swapping plans, and a 64-track routed
  scenario added to the performance gate, measured against the quality
  bar.

### Slice 2 — Routing in the model (format v7)
- A master track in every project (migrated in), track outputs (the
  master, a group, or a hardware output pair), sends (to a return, level,
  pre or post fader), polarity, input trim, and the project's pan law.
- Each edit is a named `Document` method; cycles are refused (R4).
- **Pass:** migration v6 to v7 with a golden fixture; validation tests;
  undo of every routing edit.

### Slice 3 — Group tracks
- Ctrl+G groups the selected tracks, Ctrl+Shift+G ungroups (one step
  each); drag tracks into and out of a group; groups nest; a group folds
  to hide its children (distinct from a track's height folding, shown as
  specimens first).
- A group header shows its children's activity in its lane. Mute, solo
  and arm on a group act sensibly on its children (part of slice 4's
  rules).
- **Pass:** E2E grouping, nesting, ungrouping and undo; golden renders of
  nested sums.

### Slice 4 — Mute, solo, returns, master and cue
- Solo keeps the paths of soloed tracks audible (their groups and the
  returns they feed); returns are solo-safe; exclusive and additive solo
  (the owner chooses the default); solo and mute shown on every affected
  header.
- Return tracks and the master track in the arrangement (Ableton places
  them at the bottom), with sends on track headers.
- A cue bus to a chosen hardware pair, for preview and cue listening; the
  metronome's output routing (deferred from M2).
- **Pass:** the solo rules as a pure function with a table of cases
  (reviewed with the owner first), E2E solo and mute across groups and
  returns.

### Slice 5 — The mixer panel and meters
- The Mixer tab: a channel strip per track (name and colour, input trim,
  polarity, sends, pan, fader in dB, meter with peak hold and clip
  indicator, mute, solo, arm, output). Strips follow the arrangement's
  order and groups; the master at the right.
- Meters: peak with hold and clip indicators and RMS, on track headers
  too; on the master, LUFS (momentary, short-term, integrated) and true
  peak. Levels are measured on the audio thread and read lock-free.
- Fader, pan and send controls follow the design system's value slider
  (double-click resets, type a value, Shift for fine, wheel).
- **Pass:** specimens chosen by the owner; E2E for every control by
  name; meter golden values (a 0 dBFS sine reads 0.0, LUFS on reference
  signals within 0.1 LU); idle repaints unchanged; frame times with
  meters on 200 tracks.

### Slice 6 — Sidechain and delay compensation foundations
- The graph takes a sidechain edge from any track into a node's second
  input; it becomes selectable when devices have sidechain inputs (the
  compressor in M8, VST3 in M6).
- Each node reports its latency; the plan delays parallel paths so they
  line up, and the transport bar shows the project's compensation (0 ms
  until there are latent devices).
- **Pass:** with a synthetic latent node, parallel paths line up sample
  for sample, sends and sidechains included.

### Slice 7 — Walkthrough, review and report
- The exit criterion as an E2E scenario and by hand (MT-MIX-*): route a
  drum group and a vocal through a return reverb send (a synthetic test
  return until the built-in reverb in M8), solo and mute across them.
- The end-of-milestone review (owner rule), its fixes, docs,
  measurements and the report.

## 5. Owner answers (2026-10-09)

1. **Solo default:** Ableton's: a click solos only that track, Ctrl+click
   adds. Additive solo ships as the other option.
2. **The UX pass on hints:** now, as slice 0, before the mixer.
3. **Pan law default:** −3 dB constant power (proposed; not chosen
   otherwise). −4.5 dB, −6 dB and 0 dB balance per project.

## 6. Out of scope for M4
- Plugins and plugin latency (M6); the built-in compressor, reverb and
  delay (M8). M4 tests routing with synthetic nodes.
- Automation of mixer controls (M7); the override state arrives there.
- Recording, input monitoring and input meters (M9).
- Routing matrix view, mono-check and dim [S]; reference-track A/B [L].
- Freeze, flatten and bounce (M7).
