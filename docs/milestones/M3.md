# Milestone 3 — Arrangement & Project System: plan

**Status:** In progress · **Approved:** 2026-10-07 (as proposed, unsplit)

Milestone 3 turns the audio engine into a DAW you can work in. It brings the
arrangement timeline with tracks and clips, the editing that makes it useful,
and undo for everything. It also adds save and reopen, the command palette
and shortcuts, and the design and motion system that every later screen
uses.

Exit criterion (ROADMAP): a user can **create → add a track → import audio →
arrange clips → edit → save → close → reopen** and get the same project
state.

---

## 1. Starting point (inspected 2026-10-06)

| Item | Finding |
|---|---|
| Project model | `lumen-project` has a versioned, crash-safe format with migrations, atomic saves and rolling backups (22 tests). The model already has `Project`, `Track` with `TrackKind`, `Clip` with `ClipContent`, `Media`, devices and notes. Nothing in the app uses it yet. |
| App | `lumen-app` (about 4,500 lines of egui) has a single clip lane (`lanes.rs`), the ruler, the transport bar, and the audio panel and settings. The app has no tracks, selection or undo. |
| Rendering | P-UI (ADR-0004) found egui shapes too slow for 100k notes: 20 ms per frame, against 5.7 ms on the GPU-instanced path in `lumen-render` (wgpu + Vello). Normal editing views stayed within 6.1 ms per frame on egui. |
| Engine | The clip player plays one list of clips into one stereo bus. It swaps clip lists without real-time allocation. It has no per-track mute or solo. |
| Carried over | Benchmark regression gates (planned for M2, ADR-0011). Shift+Tab conflict (ADR-0015). Owner requests: motion system and M2 retrofit, scrub strip and ruler drag-zoom, drop onto a specific track, a fuller clip properties view. |

## 2. Risk register

| ID | Risk | Impact if late | Addressed by |
|---|---|---|---|
| R1 | The arrangement misses 60–120 fps with 200 tracks, 20,000 clips and waveforms. | The core view feels slow; redesign late | Slice 4: GPU path for clip bodies and waveforms from the start; a stress project in CI benchmarks |
| R2 | The undo design does not stretch to MIDI, automation and plugins later. | Rewriting every edit in M5–M7 | Slice 2: one command model for every edit (model diffs, grouped as one step), tested with property tests (edit, undo, redo gives the same state) |
| R3 | Waveform peaks for long files stall loading or use too much memory. | Slow imports, memory blow-up | Slice 4: multi-resolution peaks built in the background and cached next to the project |
| R4 | Model and engine drift: an edit shows on screen but plays wrong, or the reverse. | Users hear something else than they see | Slice 2: the engine timeline is always derived from the model; golden renders after edits |
| R5 | Animation costs idle CPU or delays input. | Breaks the quality bar | Slice 1: motion only repaints while something moves; idle CPU measured in tests |
| R6 | Save format changes break older files. | Lost work | Every slice that adds fields adds a migration test; old fixtures stay in the repository |
| R7 | egui breaking releases. | Upgrade cost grows with the UI | Upgrade only between slices; keep widgets in our own design-system module |

## 3. Slices

Each slice works end to end and closes with its tests, docs and a manual
test where a person is needed.

### Slice 1 — Performance gates (carried over from M2)
- Instruction-count benchmarks (Callgrind on Linux CI) for engine render
  (64 clips), project save and load, and the timeline build. CI fails on a
  regression of more than a set threshold.
- Frame-time and idle-CPU scenarios need the arrangement to measure, so
  they arrive with the stress project in slice 4.
- **Pass:** a deliberately slowed function fails CI; a normal change passes.

### Slice 2 — Design system, key-flow spec and motion system
- `docs/DESIGN.md` covers:
  - layout, colour tokens (dark and light), type scale and spacing;
  - the core widgets: buttons, toggles, fields, menus, popovers, track
    header and clip;
  - focus and hover states;
  - the key flows (create a project, import, arrange, edit, save).
- Motion:
  - tokens (a few durations and easing curves);
  - rules for what animates;
  - a "reduce motion" setting.
  Animation never delays input, and nothing repaints when nothing moves.
- Retrofit the M2 UI with it: the transport bar, the audio panel and
  settings window (warnings slide in), clip lanes, the start marker and
  playhead.
- Light theme and UI scaling checked at 100%, 150% and 200%.
- **Pass:** the M2 screens match the spec in both themes and at three
  scales; idle CPU stays near zero; the owner signs off on the feel.

### Slice 3 — Project model, commands and undo
- The app runs on the `lumen-project` model.
- Every edit is a command that undoes as one step. The history is visible.
- The engine timeline is derived from the model after each edit.
- New, open, save, save as, recent projects and an unsaved-changes marker.
- Imported audio is optionally copied into the project folder, with
  relative paths.
- Autosave with recovery after a crash.
- **Pass:**
  - property tests: random edit sequences, then undo all and redo all,
    give identical states;
  - save, load and compare round trips;
  - a migration test from the M1 format;
  - a killed process recovers its autosave.
- **Plan** (2026-10-07, ADR-0024), in four parts that each work end to end:
  - **3a, history core** (`lumen-project`):
    - tracks and clips held in `Arc` so a snapshot shares everything an
      edit did not touch;
    - `History` with labelled steps, merging of continuous gestures (a
      drag is one step), undo, redo and jump-to-step;
    - format v2 (loop region and view state), with a migration and a v1
      fixture;
    - property tests.
  - **3b, the app on the model:**
    - a `Document` owns the history;
    - lanes are drawn from the project's tracks;
    - import, tempo and meter edits go through the history;
    - Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y, and a visible history list.
  - **3c, files:**
    - New, Open, Save (Ctrl+S), Save As, Open recent and
      `lumen <file>`;
    - a project folder with `Samples/Imported`, and imported audio copied
      in on save (setting, on by default) in the background;
    - unsaved changes marked in the title, and a Save / Don't save /
      Cancel prompt before closing or replacing the project.
  - **3d, autosave and recovery:**
    - autosave a minute after a change, to the local app data folder;
    - a recovery banner after a crash;
    - a test that kills the process and recovers.

### Slice 4 — Tracks and the arrangement view at scale
- Track types: audio, MIDI/instrument (empty until M5), group (summing in
  M4), return and master.
- Track headers with name, colour, height, mute, solo and arm (arm is
  visual until M9).
- Track operations: add, delete, duplicate, rename, recolour, reorder by
  drag, and multi-select.
- The engine plays every track, with mute and solo.
- Clip bodies and waveforms on the GPU path. Peaks are multi-resolution,
  built in the background and cached.
- Zoom (horizontal and vertical, anchored at the pointer), scroll and pan,
  zoom to fit, follow-playhead modes, and auto-scroll near the edges.
- **Pass:** a stress project (200 tracks, 20,000 clips) stays at or above
  60 fps (target 120) while scrolling and zooming on this machine,
  measured and gated; waveforms stay crisp at every zoom.

### Slice 5 — Grid, snapping, rulers, markers and loop
- Adaptive and fixed grid, including triplets and dotted values.
- A modifier bypasses snapping; snap guides are visible.
- Ruler formats: bars and beats, time, samples and timecode.
- Scrub strip with audible scrubbing; ruler drag to zoom and scroll (owner
  requests).
- Named markers and locators with previous and next marker.
- Loop and punch regions edited on the ruler.
- **Pass:** snapping behaves the same everywhere it appears, with tests;
  the manual test passes by ear and by eye.

### Slice 6 — Clip editing
- Move and copy-drag clips across tracks with snapping.
- Trim edges, slip content, fade handles with shapes, a clip gain handle,
  and loop-extend.
- Mute, lock, rename and recolour clips.
- Drop files onto a specific track or between tracks.
- Clip, marquee and time-range selection. Cut, copy, paste, duplicate,
  delete and ripple delete work on both clip and range selections.
- A clip properties view, extending the M2 hover card.
- **Pass:**
  - every operation is undoable as one step;
  - golden renders confirm fades and gain sound as drawn;
  - a range edit on several tracks is tested.

### Slice 7 — Command palette, shortcuts and context menus
- A command registry: every command has a name, a shortcut and a palette
  entry.
- Ctrl+K opens the palette, with fuzzy search.
- Remappable shortcuts with conflict detection. The default keymap is
  Ableton-compatible, and the Shift+Tab question is settled (ADR-0015).
- Context menus everywhere, and tooltips that show shortcuts.
- **Pass:** a test checks that every registered command is reachable from
  the palette, and that no two default shortcuts conflict.

### Slice 8 — End-to-end walkthrough and wrap-up
- The exit flow as an automated test (model and engine, headless) and as a
  manual test.
- Accessibility names and focus order for the new views.
- Docs, measurements and the milestone report.
- **Pass:** the exit criterion, with the reopened project identical to the
  saved one.

it once. Undo and the model come before tracks and editing, because every
later edit is a command.

- Automation, plus split, join and consolidate (M7).
- Recording (M9).
- Export (M9).
- Warp and time-stretch (S, later).
- Take lanes (S, later).
