# M9 slice R4 — Project lifecycle: plan

**Status:** Planned 2026-10-26, branch `m9-s4-project-lifecycle` (cut from `main`
after PR #68). The owner took every recommendation the same day: P1 A, P2 A, S A
(§3). The defaults in §4 were taken unobjected. Part 1 starts next.

**Goal (M9.md §5, CLAUDE.md §6.10, §7 Project management).** A project can be
copied, turned into a template, started from one, reverted, gathered into one
folder, and given settings of its own, all without a modal dialog and without
losing work.

**Split from the plan.** M9.md lists one R4. It is too big for one branch (the
branching rule says to split first), so this document plans **R4** (the save
family and project settings) and leaves **R4b** (media pool, relink, purge) to
its own plan and branch, as R1/R1b and R2/R2b were. Scope is in §2; the choice
is §3, question S.

**Not in R4:** the media pool, relink and purge (R4b), the Export window (R5),
the Preferences window and the Projects tab of the browser (R7), tap tempo
(R7), deleting or renaming templates inside Lumen (a file-manager task for now).

## 1. What the code gives us

## 2. Design

### 2.1 Save a copy

Command `file.save_copy` ("Save a copy…", no default key; app menu and
palette). It asks where as Save As does, then writes the project to a new
folder (made as Save As makes it) **with every media file copied in**, so the
copy opens on any machine, whatever the copy preference says. The plugins are
read first, as for any save. The open document is untouched: its path, its
dirty mark, the recent list and the autosave stay as they were. The toast names
the folder. It is a file operation, so it is not an undo step.

### 2.2 Collect and save

Command `file.collect_and_save`. Like Save, but every outside file is copied
into `Samples/Imported` first, even with the copy preference off, so the folder
holds the whole project. It runs in the background with progress in the toast
and Esc to stop. Each file is written under a temporary name and renamed when it
is whole, so a stop or a crash leaves no half file under a real name; the
project file is written only after the last copy, so stopping changes nothing.
A missing file is listed in the toast and left missing (relinking is R4b). A
full disk stops the run with a message that says so and leaves what was copied
intact. An unsaved project asks where to save first, as Save does.

### 2.3 Templates

A template is a project in `Documents/Lumen/Templates/<Name>/<Name>.lumen` (moved there from beside
`settings.json` after MT-PROJ-1 run 1), with its audio inside. **Save as template…**
(`file.save_template`) opens a small floating window with a name field (the
project's name by default); Enter saves it; a name that exists is replaced after a
second Enter in the same window, never by a modal. The template holds
everything in the project and none of its undo history.

**New from template ▸** (a submenu of the app menu, and one palette entry per
template) opens the template as an unsaved project called Untitled. Its audio
still lives in the template's folder, so the first Save copies it into the new
project whatever the copy preference says (the rule already used for renders and
recordings, generalised to a list of Lumen-owned folders). The submenu ends with
**Open templates folder**.

### 2.4 Revert

Command `file.revert`, available when the project has a file and unsaved
changes. See §3, question P2.

### 2.5 Project settings

Command `file.project_settings` ("Project settings…", app menu and palette): a
floating window of the design system's pieces, one section each:

- **Audio:** the project's sample rate (44.1, 48, 88.2, 96, 176.4, 192 kHz) with
  one line saying what it governs.
- **Mixing:** pan law (the mixer menu's list) and crossfade overlaps (the switch).
- **New tracks:** the colour new tracks take: the palette in turn (as now) or one
  chosen colour.
- **Notes:** a text box; the notes are saved with the project.

Each change is a named `Document` method and one undo step (typing in the notes
merges into one step). A new project takes the **device's rate** when it is made,
not a fixed 48,000. The project's name is its file name (Save as renames it), so
the window shows it and does not edit it.

### 2.6 What the rate governs (question P1)

Under option A, consolidate, bounce and freeze write their files at the project
rate and Export (R5) defaults to it; playback still converts to the device
rate (D6). When the two differ, the render job decodes each file it needs again
at the project rate on its worker, because the library keeps only the device-rate
copy. When they match, which is the usual case, nothing is decoded twice.

## 3. Choices for the owner

Answer by label (for example "P1 A, P2 A, S A").

### P1 — What the project's sample rate does
- **A (recommended).** Renders follow it. A project joined, bounced or frozen on
  one interface gives the same files on another, and Export starts from it. Cost:
  a second decode of the used files, only when the project rate is not the
  device's. Every existing project holds 48,000 today, so on a device running at
  44.1 kHz its first render converts; Project settings changes it.
- **B.** The rate is stored and shown, and used by Export (R5) alone. Joins,
  bounces and freezes stay at the device's rate, as now (the KNOWN_ISSUES note on
  consolidate stays open). No second decode path in R4.

### P2 — What Revert does
- **A (recommended).** Reloads the saved file, so everything, including a
  plugin's own patch, is exactly as saved. A quiet prompt in the window (not a
  modal) asks first, and the unsaved version is written to `Backups/Reverted`
  before anything is dropped; the toast after says so and offers to open it.
- **B.** One undo step back to the saved state: no reload, no prompt, and Undo
  brings the changes back. Cost: changes made inside a plugin's own window are
  not in the history, so those stay while everything else reverts.

### S — Splitting R4
- **A (recommended).** R4 as in §2 now; R4b (media pool, relink, purge, and the
  clean-up of the `Renders` and `Recordings` folders in KNOWN_ISSUES) next, with
  its own plan, its own choices and MT-PROJ-2.
- **B.** One slice. A large branch with two manual tests' worth of review.

## 4. Open (defaults taken unless the owner objects)

1. **Save a copy is self-contained** (§2.1), which Save As is not when the copy
   preference is off.
2. **Collect, Save a copy and Revert's reload are not undo steps**: they change
   where files are or which file is open, not what the song is. Revert's safety
   copy and the unchanged open document are what protect the work.
3. **Templates cannot be renamed or deleted inside Lumen** in R4.
4. **Tempo and time signature stay out of the settings window** (§1).
5. **Collect never deletes** the files it copied from.

## 5. Parts (commits on the branch)

1. **Model:** format v32 (`notes`, new-track colour), migration and golden;
   `Document` methods for rate, pan law, crossfades, notes and the colour; a new
   project takes the device rate. Tests: migration, undo of each setting, the
   frozen-track and recording guards unchanged.
2. **Save a copy and Collect:** the worker's `collect` switch, per-file temporary
   names, progress and stop, the unchanged open document. Tests: a copy opens
   with its media after the originals are deleted; a stopped collect leaves no
   half file and no changed project; a missing file is listed and left.
3. **Templates:** the folder, the list, Save as template, New from template, the
   copy-in rule for Lumen-owned folders. Tests: round trip; first Save copies the
   audio in with the preference off; the same name replaces only after the second
   Enter.
4. **Revert** (per P2).
5. **Project settings window**, the commands, the menu and palette entries, their
   tooltips and keycaps from the keymap. Built on existing components; shots at
   100, 150 and 200% in both themes.
6. **Renders at the project rate** (per P1 A): the job's rate, the second decode.
   Tests: a 44.1 kHz project on a 48 kHz fake device renders a 44.1 kHz file that
   matches the same project on a 44.1 kHz device; equal rates decode once.
7. **E2E, MT-PROJ-1, docs:** scenarios by names and keys (save a copy while the
   document stays; collect with the originals removed; template round trip;
   revert; settings survive save and reopen and undo); ADR-0105; PROGRESS,
   ARCHITECTURE, `docs/manual-tests/M9.md`, `CLAUDE.md` §12.

## 6. Gates and honesty

The usual gates (fmt, clippy `-D warnings`, workspace tests, E2E, smoke, macOS
cross-clippy, WSL clippy and perf, since the model changes). The format gate is
v32's migration and frozen golden; the performance gate may move with two more
`Project` fields. **No new dependency**: the trash question belongs to R4b.

Verified here: the model, the copy and collect logic, the template round trip,
Revert, the settings, and the rate path on the fake device at 44.1 and 48 kHz.
**Not verifiable here:** the system's real file dialogs (tests answer them) and a
real interface at two rates; those are MT-PROJ-1 on the owner's machine.

## 7. Risks

1. **The second decode** is the one new cost: a project with many large files
   rendered at a rate other than the device's decodes them all. It runs on the
   worker with progress and stops on Esc, and does not happen at equal rates.
2. **A template's size.** Copying the audio makes templates large; the window
   says how much it will copy before it saves.
3. **Revert restarts plugins** (under P2 A it reopens the file): their hosts start
   again as on any open, and the saved plugin state is what they load.
4. **Existing projects say 48,000** whatever they were made on (§1); the settings
   window shows the rate, and changing it there is the way out.
