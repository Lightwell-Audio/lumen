# Milestone 5 — MIDI & Piano Roll: plan

**Status:** Approved 2026-10-10. Owner choices (§4): C1 A (built-in synth
and MIDI out), C2 A plus a way to pull the piano roll out into its own
window, C3 A, C4 A, C5 A (default taken, not asked).

**Goal (ROADMAP §5):** make Lumen a usable MIDI production environment:
MIDI devices in and out, MIDI tracks that play and monitor, recording,
the piano roll with velocity and controller lanes, quantize and its
related tools, Standard MIDI Files and MIDI learn.

**Exit criterion:** a user can record a MIDI performance, edit it in the
piano roll, quantize it, play it back and save and reopen it without
changing its musical content.

Requirements covered: CLAUDE.md §6.3 (MIDI, except MIDI effects [S] and
MPE [L]), the MIDI half of §6.9 (MIDI devices), the §7 "MIDI" and
"Recording" MIDI rows, and the computer keyboard as MIDI input.

## 1. Starting point (inspected 2026-10-10)

| Item | Finding |
|---|---|
| Model | `TrackKind::Midi` exists, and `ClipContent::Midi { notes }` stores notes as `[start, length, pitch, velocity]` in ticks (`PPQ` 1,411,200, ADR-0009). There are no controller events, program changes or per-note release velocity. MIDI tracks can be added; they play nothing. |
| Engine | The mixer graph (ADR-0035) runs a node per track, fed by audio clips. There is no MIDI event path, no instrument node and no note tracking. `Engine` already names "MIDI all-notes-off" as joining its stop handling. |
| Devices | No MIDI device layer and no MIDI dependency. Audio devices (M2) have hot-plug handling to follow. |
| Instruments | None: VST3 hosting is M6, the built-in synth and sampler M8. **Nothing can sound a note yet** (choice C1). |
| App | M4.5's widgets (switch, segmented, value slider, empty state, menus, motion) are ready for the piano roll. The detail panel has a Clip tab, greyed until now. The editing grid, snapping, selection, drags and undo (M3) are shared code the piano roll reuses. |
| Gates | Instruction-count gate (+2%), frame-time benchmark by hand (stress project: 200 tracks, 20,000 clips; the 100,000-note part of the quality bar is still unmeasured), real-time safety under the allocation guard. |

## 2. Risk register

| ID | Risk | Impact if late | Addressed by |
|---|---|---|---|
| R1 | Notes hang: a note-on whose note-off is lost on stop, jump, loop, mute, edit, plan swap or device change. | A stuck note; trust lost | Slice 1: one note tracker per instrument input, flushed on every one of those events, with an E2E scenario for each and a panic command |
| R2 | MIDI timing jitters: events land on block edges instead of their sample. | Sloppy playback and recordings | Slice 1: events carry a sample offset within the block; golden renders check note starts to the sample. Slice 6: input timestamps from the driver, corrected by the input latency |
| R3 | The piano roll misses the frame budget with 100,000 notes. | Fails the quality bar | Slice 3: notes drawn on the GPU as the clip bodies are (ADR-0026), a 100,000-note stress clip in `--bench-frames` from the first piano-roll slice |
| R4 | The computer keyboard's letters fight existing shortcuts (H, W, X, Z, M). | Keys do the wrong thing | Choice C3: a mode that takes the letters while on, shown in the transport, Esc or its toggle to leave |
| R5 | A device layer that blocks the UI (enumeration, a port that hangs on open). | Freezes | Slice 0: enumeration and opening off the UI thread, as the audio device probe does |
| R6 | Format change for controllers and program changes breaks old projects. | Lost work | Slice 0: format v11 with a migration and golden fixture; notes keep their compact form |
| R7 | Quantize loses the performance. | Can't undo a feel | Slice 5: quantize is an undoable edit; recorded timing kept alongside (the [S] "restore recorded timing" if cheap; otherwise recorded for later) |

## 3. Slices

Every slice ends with E2E scenarios for what it delivers, the smoke
tests, and a manual test (MT-MIDI-*). New visuals (the piano roll, lanes,
note colours, the quantize popover) are shown as rendered specimens before
building, and behaviour variants pitched with a recommendation.

### Slice 0 — MIDI devices and the model (format v11)
- A MIDI device layer (midir, MIT; WinMM on Windows, CoreMIDI, ALSA):
  inputs and outputs listed with switches for Track and Remote, hot-plug,
  opened off the UI thread. A MIDI page in the settings window.
- Format v11: controller, pitch-bend, pressure and program events in MIDI
  clips beside the notes, with a migration and a golden fixture.
- **Pass:** devices appear and disappear with hot-plug (E2E on a virtual
  test device); the format round-trips; old projects open unchanged.

### Slice 1 — Hearing MIDI: the event path and an instrument
- MIDI events through the mixer graph: a MIDI track's node takes events
  with sample offsets, feeds its instrument, and the instrument's audio
  carries on as an audio track's does (volume, sends, groups).
- The instrument chosen in C1, plus "MIDI To" for external hardware.
- Notes never hang (R1): one tracker per instrument input, flushed on
  stop, jump, loop, mute, edit, plan swap and device loss; Panic.
- Sustain, pitch bend, aftertouch and program/bank change pass through.
- **Pass:** golden renders (note starts to the sample, sustain holds, a
  loop wrap releases), every hang case as an E2E scenario, zero heap
  operations while playing.

### Slice 2 — Playing live: monitoring, thru and the computer keyboard
- "MIDI From" per track (all inputs, a device, a channel) and monitoring
  In / Auto / Off, as audio tracks will have it: an armed or selected MIDI
  track plays what comes in (MIDI thru).
- The computer keyboard as a MIDI keyboard (C3), with octave and velocity
  keys and an indicator in the transport.
- **Pass:** E2E plays the keyboard into a track and hears it; a manual
  test with the owner's MIDI controller, if one is available (§5).

### Slice 3 — MIDI clips and the piano roll
- MIDI clips in the arrangement: create one (double-click an empty MIDI
  lane, or a command), see its notes drawn on the clip body, and every M3
  clip edit (move, trim, loop-extend, split, duplicate, mute, colour).
- The piano roll (C2): draw, select, marquee, move, resize, split, glue,
  mute, duplicate, nudge, transpose, legato; note audition while editing;
  zoom and snap shared with the arrangement; notes on the GPU.
- **Pass:** E2E for every edit and its undo; `--bench-frames` with a
  100,000-note clip at p99 inside the 120 fps target.

### Slice 4 — Velocity and controller lanes
- A velocity lane (drag a stem, draw across stems, box-select), and lanes
  for CC, pitch bend and pressure, with pencil, line and curve tools.
  Curves reuse `lumen_core::curve` (the fades' free curves, ADR-0031).
- **Pass:** E2E draws each lane and plays it back; golden renders for
  pitch bend and CC timing.

### Slice 5 — Quantize and its tools
- Quantize: grid from whole note to 1/128 with triplet, dotted and custom
  values; start, end, start and end, or length; strength, swing,
  sensitivity window and iterative mode. Q applies the last settings;
  Shift+Q opens the options popover with a live preview (C5).
- Humanize (timing and velocity), legato, fixed length, transpose,
  scale-constrain and reverse, as commands on the selected notes or clips.
- **Pass:** unit tests for every mode against hand-worked cases; E2E Q and
  Shift+Q; one undo step each.

### Slice 6 — Recording MIDI
- Record, overdub and replace (C4), count-in, punch in and out, recording
  on several armed tracks at once, crash-safe capture (an in-progress
  recording survives a crash through autosave).
- Input timing: driver timestamps, corrected by the input latency, so
  recorded notes land where they were played.
- **Pass:** E2E records from the virtual device and checks note positions
  to the sample; the owner's manual test with a controller.

### Slice 7 — Files, learn and clock
- Standard MIDI File import and export (clips and tracks, type 0 and 1,
  tempo and time-signature maps).
- MIDI learn for any parameter (mixer controls now, plugin parameters
  when M6 arrives), with a mapping list; MIDI clock out.
- **Pass:** SMF round-trips its notes, controllers and tempo map (golden
  files); E2E learns a fader from the virtual device.

### Slice 8 — Close
- The exit walkthrough as E2E (record a part, edit it, quantize, play,
  save and reopen with identical content) and its manual test; the
  `lumen-review` review and its fixes; the report.

## 5. Testing limits

- No physical MIDI controller has been listed for the owner's machine.
  E2E drives a virtual device; manual tests need a controller (or a
  virtual port such as loopMIDI) to check real timing.
- Hardware "MIDI To" needs an external instrument, or the OS synth.
- macOS and Linux MIDI by cross-target clippy and CI only.

## 6. Not in this milestone

- MIDI effects (arpeggiator, chord, scale, velocity, note length) [S] →
  M8 with the built-in devices.
- Drum maps, the drum editor and the step sequencer → M8.
- Loop recording into takes and Capture MIDI [S] → M9.
- Scale highlighting, fold, ghost notes, multi-clip editing, step input
  [S] → after the core piano roll, if time allows in slice 3 or 4;
  otherwise M10.
- MPE and MIDI 2.0 [L].
