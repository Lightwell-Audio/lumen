# M9 slice R2 — Audio recording: plan

**Status:** Planned 2026-10-25, branch `m9-s2-audio-recording` (cut from `main`
after PR #62). Owner choices taken the same day: punch A, loop A, loopback
helper as its own slice R2b (§3). Nothing is built yet.

**Goal (M9.md §5, CLAUDE.md §6.2).** Arm one or many audio tracks, press
Record, and get a clip per track that plays what came in, placed where it was
played. A crash costs at most the last second. The audio thread never waits
for the disk.

**Not in R2:** Takes menu and loop passes cut into clips (R3), Capture MIDI
(R3), the loopback helper (R2b), the Preferences window (R7; the offset field
lives in the audio settings window until then), streaming playback (R6).

## 1. What the code gives us

| Area | Fact | Consequence |
|---|---|---|
| Input in the engine | `InputPlayer::input` holds the block's channels; `render` knows `cx.start`, `cx.device`, `cx.stream`, `cx.recording`, `cx.looping`. | The capture is a second job of `InputPlayer`: in `render`, while `cx.recording`, copy the routed channels of the held block with their heard timeline position. Parts never cross a loop wrap or a locate, so each copy is contiguous. |
| Heard position | `midi::capture::heard` turns a device frame into the timeline sample heard at that moment. | Audio uses the same rule, then the app subtracts input plus output latency and the manual offset (R4 A) when it places the clip. |
| Record command | `Command::Record { count_in }`, `EndRecord`, `recording` set after the count-in; the app's `Record` session handles MIDI tracks only (`start_recording` filters `TrackKind::Midi`). | Count-in, metronome, Stop and loop come free. The session grows an audio half; both can record together. |
| Edit guard | `History::guard_recording(tracks)` refuses edits to a track being recorded (R0). | Reuse for audio tracks. |
| WAV writer | `lumen_media::wav::Writer` writes to a temp name and renames on `finish`; it is invalid until then. | A new `take` writer: valid at every moment (§2 D3). |
| Where files live | Renders go to `Renders` beside the autosaves and are copied to `Samples/Rendered` on Save (ADR-0095). | Takes follow it: `Recordings` beside the autosaves, copied to `Samples/Recorded` on Save. |
| Latency | `AudioInfo.input_latency` and `output_latency` in frames. | Automatic shift; one new settings field for the manual offset. |
| Test input | The `test-input` driver's `FakeControl::input_levels` sets a DC level. | Add a ramp source so placement is checkable to the sample. |

## 2. Design

**Capture (engine, real time).** `InputPlayer` gets a `CaptureRoute` list
(track, channel, stereo, armed-to-record) beside the monitor routes, replaced
through a queue like them. While `cx.recording && !cx.tail`, each part pushes
one chunk per route into a preallocated SPSC ring: a small header
(`track`, heard timeline sample of its first frame, frames, loop pass) and the
samples. Sized for 8 seconds of 32 channels. A full ring drops the chunk and
bumps an overrun counter; the disk side sees the gap from the next chunk's
position and pads zeros, so the take stays aligned. No allocation, lock or
block (hard rule 1), under `rt_section` in tests.

**Disk side (a worker thread).** Drains the ring, writes each route's file.
**Float WAV, one file per take, one per armed track** (D1; a stereo input is
one stereo file), at the device rate. The writer (`lumen-media`) writes the
header with a data length of 0, flushes the header with the true length about
once a second and on stop, and so is valid at every moment (D3). Beyond 4 GiB
it must be RF64 or continue in a second file; step 1 settles which by testing
what the decoder reads. A write error ends that track's take, keeps what was
written, and says so.

**Punch (owner A).** The worker is given the punch window in timeline samples
and drops frames outside `[in, out)`; the file starts at punch in. Without
punch, the file starts at the first frame after the count-in.

**Loop (owner A).** The worker writes the chunks straight through; the clip is
one long clip from the take's start for its whole length (the loop pass number
is stored with the take for R3, which cuts the same file).

**Placement.** On stop the app closes the files, imports each as media (the
existing import path), and places one clip per track at
`first heard sample − (input + output latency + manual offset)`, the source
offset skipping any part before 0. One undo step: `Document::record_audio_take`
replaces what the clip covers (the M3 overlap rule), like a MIDI take in
Replace mode.

**While recording.** The arrangement draws a clip growing on each recording
track from live peaks the worker publishes (an `Arc` read each frame, no lock
on the audio path); the existing recording look (red rail, take bounds) is
reused. Editing that track is refused with the R0 note. The status popover
shows overruns and disk write rate.

**Crash recovery (D3).** At start the worker writes a small sidecar
(`<take>.take.json`: track id, timeline start, latency shift, rate, project
session) and removes it at a clean stop. The recovery pass (`app/recovery.rs`)
finds files in `Recordings` whose sidecar is still there, repairs the header
from the file length, and offers them as clips on their tracks in one undo
step, with a notice. A track that no longer exists keeps its file in the media
pool.

**Offset.** `AudioSettings.record_offset_ms` (an added field, absent means 0,
no version change as R1's `all_inputs`), a number field in the audio
settings Latency section, applied at placement. Positive moves the take
earlier.

**Format.** No format change planned: clips and media already carry what a
take needs. If the placement shows otherwise, bump the format and say so.

## 4. Parts (commits on the branch)

1. **Take writer** in `lumen-media`: valid-at-every-moment WAV, header refresh,
   repair from file length, large-file decision (RF64 or continuation).
   Tests: truncate at every byte, kill-style drops, decode what remains.
2. **Capture in the engine:** routes, ring, chunks, overrun count, gap padding
   contract. Tests: positions across blocks, loop wrap, count-in, allocation
   guard; fake-input ramp.
3. **Worker and session:** disk thread, punch window, peaks, stop and finish;
   the app's session records audio tracks, with MIDI together.
4. **Placement and undo:** `Document::record_audio_take`, latency and offset,
   `Samples/Recorded` on Save, `Recordings` folder, history guard.
5. **Arrangement and settings:** growing clip, overrun and disk read-out,
   the offset field, arm-with-no-input message, commands and palette entries.
6. **Recovery** of unfinished takes.
7. **E2E, MT-REC-2, docs:** scenarios on the fake backend with the ramp input
   (record, punch, loop, count-in, undo, save and reopen, kill and recover);
   ADR-0102; `PROGRESS.md`, `ARCHITECTURE.md`, `CLAUDE.md` §12.

## 5. Gates and honesty

The usual gates (fmt, clippy `-D warnings`, workspace tests, E2E, smoke,
macOS cross-clippy, WSL clippy and perf for engine and project changes).
Verified here: the writer, the capture positions, placement and recovery on
the fake backend. **Not verifiable here:** real latency compensation accuracy,
ASIO and WASAPI capture under load, and the kill-and-reopen on the owner's
machine; those are MT-REC-2 on the Focusrite.

## 6. Risks

1. **Heard-position error at the loop wrap or a locate** puts a take off by a
   block; covered by the engine tests and the ramp E2E, not by ear.
2. **A slow disk at 64 frames** overruns the ring; the counter shows it and
   the gap is padded rather than shifted.
3. **RF64 reading** may not be supported by the decoder; part 1 decides
   before anything depends on it.
4. **Latency figures from WASAPI are estimates** (ADR-0100): until R2b's
   loopback helper measures them, the manual offset is the correction.
